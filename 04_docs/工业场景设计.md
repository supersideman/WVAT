# 工业场景设计 · 方向转变

> 立项时间：2026-11-21
> 状态：**设计定稿，待实施**（阶段 0 未开工）
> 一句话：**从"消费电子遥控器"转向"人员禁入环境的便携式监控与操作终端"，并在中间加入 AI 辅助决策层。**

---

## 一、为什么转

原方向是消费电子（切歌、调音量、锁屏），问题在于：

| 问题 | 说明 |
|---|---|
| 动作太"轻" | 播放/暂停没有工程含量，答辩讲不出技术深度 |
| 没有可靠性要求 | 丢一条指令重发一次就行，不涉及安全 |
| 演示不震撼 | "手表控制电脑切歌"更像玩具 |

转向工业后的收益：

| 收益 | 说明 |
|---|---|
| 场景刚需 | 人员不能进入，终端是**唯一的感知与控制手段** |
| 有安全命题 | 误操作有物理后果 → 联锁、确认、急停、留痕都有了依据 |
| AI 有落点 | 工业现场"数据多、人疲劳、判断难"，正是 AI 该介入的地方 |
| 与我们已做的能力吻合 | 心跳、回执、超时、去重，从"体验优化"变成"安全机制" |

## 二、场景定义

```
┌─────────────── 密闭工艺舱（人员禁入）───────────────┐
│  执行器：加热器   循环泵   进气阀   排气阀           │
│  传感器：温度     压力     气体浓度 液位   舱门状态   │
│                                                      │
│  禁入原因：高温 / 有毒气体 / 缺氧                    │
└──────────────────────┬───────────────────────────────┘
                       │ 唯一通道
                 ┌─────┴─────┐
                 │  便携终端  │  手表（戴手上）+ 手机（兜里当中继）
                 └───────────┘
                    安全区里的人
```

**终端职责**
1. **看**：实时工况（温度/压力/气体/液位/设备开停/报警）
2. **控**：启动/停止执行器、报警确认、复位、急停
3. **判断辅助**：AI 给出趋势预测与操作建议

## 三、系统架构

### 三层结构

| 层 | 职责 | 实现位置 |
|---|---|---|
| **感知层** | 采集工况；维护设备状态机；fail-safe | PC 上的仿真器 |
| **决策辅助层** | 趋势预测、联锁校验、意图理解、风险解释 | **手机 App（AI 在这里）** |
| **执行层** | 真正执行动作 + 失联自动进安全状态 | 仿真器 + 设备 |

手表是**人机界面**：显示数据、采集意图、展示 AI 建议、接收确认。

### 双链路（演示时互为备份）

| 模式 | 链路 | 用途 |
|---|---|---|
| **A（主场）** | 手表 → 蓝牙 → 手机 → WiFi/HTTP → 仿真器 | 便携叙事：人拿着手表走动，手机做中继 |
| **B（兜底）** | 手表 → 蓝牙 → 电脑 → 仿真器 | 少一跳，现场网络异常时切换 |

两套**共用同一个仿真器与同一套协议**，手表端零改动。

## 四、AI 辅助决策设计（核心创新点）

### 4.1 人在回路（Human-in-the-loop）

```
        人的意图
           ↓
   ┌───────┴────────┐
   │   AI 辅助层     │   ① 理解意图：这个按钮/这句话想干什么
   │                │   ② 评估风险：当前工况允许吗？后果是什么？
   │                │   ③ 给出建议：可行方案 + 理由 + 预期影响
   └───────┬────────┘
           ↓
   ┌───────┴────────┐
   │   人确认        │   ← 决策权始终在人
   └───────┬────────┘
           ↓
        设备执行
           ↓
   结果回显 + 操作留痕
```

**核心原则：AI 不直接控制设备。** 它做"建议/预测/解释"，最终执行由人确认。
理由：可解释性、可追责、误动作有物理后果。

### 4.2 AI 的两个角色

| 角色 | 时机 | 做什么 |
|---|---|---|
| **哨兵** | 平时（无人操作） | 盯趋势、提前预警、评估设备健康度 |
| **参谋/守门员** | 指令下发时 | 解读意图、校验联锁、拒绝危险操作并说明原因 |

> 工业事故多数不是"操作错了"，而是"没人注意到工况在恶化"——所以**哨兵可能比守门员更值钱**。

### 4.3 四项能力（按优先级）

| # | 能力 | 做法 | 难度 | 优先级 |
|---|---|---|---|---|
| 1 | **趋势预测** | 滑动窗口最小二乘拟合斜率 → 外推到阈值 → 剩余时间（"预计 3 分钟后超 85℃"）| ⭐⭐ | 必做 |
| 2 | **联锁合法性校验** | 规则引擎 + 自然语言解释（"拒绝：液位 12% 低于 20% 下限，干烧风险"）| ⭐⭐ | 必做 |
| 3 | **自然语言指令** | 语音/文字 → LLM 解析成结构化动作提案 → 人确认 → 下发 | ⭐⭐⭐ | 加分 |
| 4 | **异常模式识别** | SPC 控制图 / 滑动窗口 z-score，识别"形态异常"而非"超限" | ⭐⭐⭐ | 有余力 |

### 4.4 可解释性要求

每条 AI 建议**必须附带依据**，例如：

```
建议：暂缓启动加热
依据：近 2 分钟温度斜率 +1.8℃/min；液位 12%（<20% 下限）
预计：若继续加热，3 分钟后温度达 85℃ 上限，且存在干烧风险
```

### 4.5 降级策略（AI 不能是单点故障）

| 场景 | 设计 |
|---|---|
| AI 不可用（断网 / LLM 超时）| 简单指令仍可执行（本地联锁规则兜底），界面明示"AI 辅助不可用" |
| 高风险操作 + AI 不可用 | 退回**双人确认**或禁止执行 |
| AI 建议有误 | 建议必须带依据，人可判断错在哪 |

> 论文表述：**AI 是增强，不是依赖。**

## 五、协议设计（草案）

### 5.1 动作码（替代原媒体键 A01~A08）

| 码 | 动作 | 安全要求 |
|---|---|---|
| A21 | 进料/循环泵 启停 | 启动需确认 |
| A22 | 加热器 启停 | 启动需 AI 校验 + 确认 |
| A23 | 进气阀 开闭 | 无需确认 |
| A24 | 查询状态 | — |
| A25 | 报警确认 | — |
| A26 | 复位 | 需确认 |
| A99 | **急停**（全部停止）| **长按 2 秒** |

### 5.2 状态回显帧

```
OV+EV=IO,<泵>,<加热>,<阀>,<温度>,<压力×10>,<液位>,<气体>,<报警码>
例：OV+EV=IO,1,0,1,68,24,55,12,0
     泵运行 / 加热停 / 阀开 / 68℃ / 2.4MPa / 液位55% / 气体12ppm / 无报警
```

长度约 35 字符，固件 96 字节行缓冲够用。

### 5.3 AI 建议帧（新增）

```
OV+EV=AI,<建议码>,<参数>,<时限秒>
例：OV+EV=AI,ALERT_TEMP,850,180     → 温度预计 180 秒后到 85.0℃
```

### 5.4 失联兜底

| 端 | 机制 |
|---|---|
| 手表 | 5 秒收不到状态帧 → 界面显示红字"失去监控" |
| 仿真器 | 10 秒收不到终端心跳 → 自动进安全状态（停加热、关进气阀）|

## 六、手表 UI 重构

工业终端的核心是"看"，现在的主界面是"点图标发指令"——顺序反了。

```
锁屏（时间 + 报警灯：绿色正常 / 红色报警）
  ↓ 上滑
【监控页】← 新的主界面
   68℃  2.4MPa
   液位 55%   气体 12ppm
   [加热 运行] [泵 停] [阀 开]
   报警：超温 / AI：预计 3 分钟后超限
  ├ 左滑 → 【控制页】动作格 + 急停长按
  └ 右滑 → 【设置页】（亮度 / 蓝牙 / 城市 / 版本）
```

- 日期页不再单独占一页（工业场景里日期不是重点），缩到锁屏/监控页顶部小字
- 报警用颜色 + 图形（无蜂鸣器时靠视觉）

## 八、答辩叙事（创新点 / 工作量 / 对比）

### 创新点（按分量排序）

1. **面向人员禁入环境的便携终端**（场景刚需，替代人工进入）
2. **人在回路的 AI 辅助决策**（AI 建议 + 人确认，可解释、可追责）
3. **失效安全设计**（失联自动进安全状态、双链路冗余、操作留痕）
4. **端-边协同分层**（手表做界面、手机做 AI、仿真器做设备）

### 与传统方案的对比

| 维度 | 传统工业 HMI | 本方案 |
|---|---|---|
| 形态 | 固定式触摸屏，需人员在现场 | **便携可穿戴**，人不用进危险区 |
| 报警 | 阈值报警（超了才响）| **趋势预测**（提前 N 秒预警）|
| 操作 | 人凭经验判断 | **AI 校验 + 建议 + 理由** |
| 责任 | 操作日志在 PLC 里 | 终端本地留痕 + 可追溯 |
| 失效 | 断线即失联 | **fail-safe + 双链路** |

### 可讲的技术点（已实现、有实测证据）

- 蓝牙 SPP 双向链路、心跳/回执/超时/去重（手机端实测日志）
- 固件：LVGL 三页导航、TLS 无关的自研协议、LUT 图元图标（零位图零字库）
- 手写 RTC（不依赖 HAL 模块）、PWM 背光、中文子集字库（3755 字）
