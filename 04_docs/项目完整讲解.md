## 1. 项目是什么

### 1.1 一句话

**戴在手腕上的便携控制终端**：在手表屏幕上点一下（或后续用语音说一句），
由电脑执行对应动作，结果回到手表屏幕上。

**它不是什么**：
- 不是智能手表（不能独立联网、不能装 App、没有心率等传感器）
- 不是语音助手（目前语音还未接入，是下一步工作）
- 不做"通用电脑控制"（只做**白名单内的固定动作**，这是安全设计）

### 1.2 硬件平台与资源边界

| 项目 | 规格 | 对设计的约束 |
|---|---|---|
| MCU | STM32F411RET6，Cortex-M4F | 512KB Flash / 128KB SRAM |
| 屏幕 | 240×280 IPS，SPI 接口 | 分辨率小 → 图标必须极简 |
| 触摸 | CST816（I2C） | **轮询式采样、点稀疏** → 手势判定不能依赖速度 |
| 外部 Flash | W25Q128（16MB，SPI） | 可挂文件系统，目前未用 |
| 联网 | **无 WiFi / 无 TCP-IP** | **必须依赖 PC 网关** |
| 蓝牙 | 有模块但未启用 | SPP 理论上可行，稳定性待评估 |
| 音频 | 无麦克风、无喇叭（未接线） | 语音需要外接 I2S 麦（PB12/PB13/PB15 空闲） |

> **这张表决定了整个架构**：手表算力与联网能力都不足以独立完成"理解意图"，
> 所以设计成"手表只负责采集与显示，PC 负责理解与执行"。

### 1.3 目前实现的功能

| 功能 | 入口 | 状态 |
|---|---|---|
| 锁屏 + 跟手滑动解锁 | 开机默认 | ✅ |
| 播放/暂停音乐 | 主界面 ♪ | ✅ |
| 下一首 | 主界面 ▶\| | ✅ |
| 我困了（静音+锁屏+关屏） | 抽屉 | ✅ |
| 音量 + / − | 抽屉 | ✅ 可回读百分比 |
| 打开资料（默认桌面） | 抽屉 | ✅ |
| 查状态（时间+在线） | 抽屉 | ✅ |
| 语音 | 抽屉麦克风 | ⬜ 仅占位 |

### 2.1 三层职责

```
                     ▼
┌─────────── PC 网关（Python，纯标准库）───────────────────────────┐
│  transport.py  通道：TCP（联调）/ 串口（真机，掉线自动重连）        │
│  protocol.py   OV+ 协议：组帧、解析、文本清洗                      │
│  gateway.py    主循环：收帧→去重→路由→执行→应答，含心跳            │

│  run_gateway.py 启动器：自动找 CH340 串口                         │
└───────────────────────────────────────────────────────────────────┘
                     │ Win32 API / CoreAudio
                     ▼
              电脑系统（媒体播放、锁屏、音量、文件）
```

### 2.2 三条设计原则

**① 界面与链路解耦**

UI 完全不知道串口的存在。`ui_main.c` 只提供一个"意图回调"钩子：

```c
typedef void (*ui_intent_cb_t)(ui_icon_t kind);
void ui_main_set_intent_cb(ui_intent_cb_t cb);   /* 由链路层注册 */
```

点击时：注册了回调就交给它（真机发指令）；没注册就在本地假装成功（方便单独调 UI）。
将来要换成蓝牙/网络，只改链路层，UI 一行都不用动。

**② 中断只做最少的事**

串口中断只负责"把字节攒成一行 + 置标志"，**绝不在中断里操作 LVGL**。
LVGL 不是线程安全的，改控件必须在 LVGL 任务上下文里做。
界面更新交给一个 30ms 的 `lv_timer`。

**③ 一切可验证**

每个动作都要能回答"它到底做了没"。手段有三个：
音量**回读百分比**、顶部**圆点三态**、**3 秒超时**变红。
原因见《问题与尝试记录》：曾经有一整类动作"返回成功但实际没发生"。

## 3. 通信协议（OV+）

### 3.1 帧格式

全部是 **ASCII 文本行 + `\r\n` 结尾**，载荷用 UTF-8。

| 方向 | 帧 | 例子 |
|---|---|---|
| 终端→代理 | `OV+AI=<ID>,<CODE>[,<ARG>]` | `OV+AI=5,A04` |
| 代理→终端 | `OV+AR=<ID>,<STATUS>,<TEXT>` | `OV+AR=5,OK,音量已调高 63%` |
| 代理→终端 | `OV+EV=<EVENT>,<TEXT>` | 预留（异步事件） |
| 双向 | `OV+PING` / `OV+PONG` | 心跳 |

`STATUS` 取值：`OK` / `ERR` / `BUSY`。

### 3.2 为什么用文本行而不是二进制

| 理由 | 说明 |
|---|---|
| 可调试 | 串口助手直接能看到内容，不用写解析器 |
| 前向兼容 | 新增字段不影响旧解析；不认识的行直接忽略 |
| 实现简单 | 两端都只是字符串拼装，无序列化依赖 |
| 代价 | 比二进制多几个字节，在 115200 下完全可接受 |

### 3.3 REQ_ID 与幂等去重（重要设计）

`REQ_ID` 是 **uint8**（0~255 循环递增），用途是**去重**：
同一 ID 的重复请求只执行一次，直接回缓存结果。

这样设计是为了应对"重传"场景：网络/串口丢包后重发，不会把音量调两次。

**两个必须处理的边界条件**（都是实机踩出来的）：

```python
# ① 设备复位：手表重新上电后 REQ_ID 从 1 重来，
#    而网关还记着上一轮的 1..N → 会把全新请求当成重传而静默丢弃
if req_id < self.last_req_id and self.dedup:
    self.dedup.clear()

# ② 心跳超时：设备可能已复位
if self.missed_pong > MAX_MISSED_PONG:
    self.dedup.clear()
```

> 副作用：REQ_ID 从 255 回绕到 1 时也会触发一次清空，
> 代价是极小概率重复执行一次动作。相比"吞掉新指令"，这个代价可接受。

### 3.4 文本清洗与长度限制

```python
MAX_TEXT_BYTES = 60          # 屏幕上显示得下的量级，约 20 个汉字
def clean_text(text):
    text = text.replace("\r"," ").replace("\n"," ").strip()
    # 按**字节**截断，且保证不把多字节汉字切成半个
    while len(text.encode("utf-8")) > MAX_TEXT_BYTES:
        text = text[:-1]
```

为什么按字节而不是按字符：UTF-8 下一个汉字 3 字节，
若按字符截断，60 个汉字会变成 180 字节，超出屏幕也超出缓冲区预期。

### 3.5 心跳与断线重连

- 网关每若干秒发 `OV+PING`，连续多次没收到 `OV+PONG` 判定掉线。
- 串口可以拔线/板子复位，pyserial 会抛 `SerialException`。
  **必须捕获，否则整个网关进程崩溃**：

```python
try:    n = self._ser.in_waiting
except Exception:  self._drop(...)     # 只标记掉线，不抛
# 之后每 2 秒尝试重开，插回来自动恢复
```

## 4. 手表端（固件）详解

### 4.1 先补几个 LVGL 概念

看懂代码需要知道 LVGL 8.2 的五个概念：

| 概念 | 说明 | 本项目对应 |
|---|---|---|
| **对象树** | 一切皆 `lv_obj`，父子成树；子对象坐标相对父对象 | 屏幕 → 舞台 → 层 → 卡片 → 图标 |
| **屏幕（screen）** | 特殊的顶层对象，用 `lv_scr_load()` 切换 | 舞台屏幕、抽屉屏幕 |
| **样式（style）** | 颜色、圆角、边框等属性集合；可继承、可按状态覆盖 | `ui_theme.h` 定义，`box()` 应用 |
| **状态（state）** | `LV_STATE_PRESSED` 等；同一对象在不同状态可有不同样式 | 按下变亮一档 |
| **定时器（lv_timer）** | 在 LVGL 任务里周期回调 | 30ms 派发回执、200ms 超时检查 |
| **事件（event）** | 点击、按下、拖动等；`lv_obj_add_event_cb` 注册 | 格子点击、锁屏拖动 |

**一个必须记住的陷阱**：
`lv_obj_set_pos()` / `lv_obj_set_size()` 写的其实是**样式属性**，
而 `lv_obj_remove_style_all()` 会把这些**一起清掉**。
所以"先设坐标再清样式"会导致坐标归零（本项目踩过，见《问题与尝试记录 §2.3》）。

### 4.2 `ui_theme.h` —— 唯一真源

所有颜色、坐标、尺寸、阈值都在这里，`.c` 文件里不写魔法数字。

```c
/* 配色 */
#define UI_C_BG      0x0E1116   /* 背景近黑 */
#define UI_C_CARD    0x1B2129   /* 卡片（比背景亮一档） */
#define UI_C_BTN     0x0A1218
#define UI_C_TEXT    0xE8EDF2
#define UI_C_DIM     0x5C6B7A   /* 次要信息 */
#define UI_C_PRESSED 0x2E3947   /* 按下态 */
#define UI_C_ACCENT  0x35D0BA   /* 强调（青） */
#define UI_C_DANGER  0xFF5C5C
#define UI_C_WARN    0xFFC24B
#define UI_C_INFO    0x4A9EFF

/* 主界面布局 */
#define UI_RESULT_Y  84         /* 回执横条 */
#define UI_TILE_Y    122        /* 三个意图格 */
#define UI_TILE_SIZE 66
#define UI_TILE_STEP 75         /* 66 宽 + 9 间距 */
#define UI_BTN_Y     198        /* 麦克风按钮 */

/* 锁屏 */
#define UI_LOCK_SWIPE_PX 80     /* 上滑 80px 解锁 */

/* 抽屉 */
```

**一个额外好处**：设计预览脚本 `03_design/render_c_preview.py` 会**解析这个文件**
来生成效果图，所以图片和代码永远一致。

### 4.3 `ui_icons.c` —— 13 个图标，零位图

**问题**：LVGL 8.2 **没有填充多边形/三角形图元**。要画出好看的图标只有两条路：
引入图片（占 Flash、要转换工具）或用基本图元拼。这里选后者。

**只用两种原语**：

| 原语 | 实现 | 用途 |
|---|---|---|
| `put()` | 带圆角的 `lv_obj` 矩形 | 实心块：话筒、列表条、音量后板 |
| `polyline()` | `lv_line` 折线 | 线条：返回箭头、感叹号 |

**关键技巧：台阶法**
用几级高度递减的矩形拼出三角形。以"下一首"为例：

```c
int h = px(s, 3, 5);         /* 底部总高 = 尺寸的 3/5 */
int stepw = px(s, 1, 9);     /* 每级台阶宽 */
for (int i = 0; i < 4; i++) {
    int hh = h - (h * i) / 4;         /* 逐级变矮 */
    if (hh < 2) hh = 2;
    put(p, x0 + i * stepw, cy - hh / 2, stepw + 1, hh, 0, c);
}
put(p, x0 + 4 * stepw + 1, cy - h / 2, barw, h, 0, c);   /* 尾部竖条 */
```

同理，喇叭锥体用 3 级**递增**台阶（`vol_cone()`），对勾用两段折线。

**为什么不用描边三角形**：28px 尺寸下描边只剩两根细线，
实测"下一首"看起来像 `▷|`（两根线），完全认不出。改成实心台阶后一眼可辨。

**全部 13 个图标**：
音符、月牙、文件夹、田字格、麦克风、下一首、音量+、音量−、列表、齿轮、对勾、叉、返回箭头。

**统一入口**：

```c
void ui_icon_draw(lv_obj_t *parent, ui_icon_t kind,
                  int cx, int cy, int size, uint32_t color);
```

所有图标按 `size` 等比缩放（内部 `px(size, num, den)` 计算），
所以调用方只关心"画多大、画在哪、什么颜色"。

### 4.4 `ui_main.c` —— 主界面层

它不是屏幕，而是**把内容画进传入的容器**：

```c
void ui_main_build(lv_obj_t *parent);
```

这样设计是为了让 `ui_stage.c` 能把"锁屏层"和"主界面层"放进同一个可拖动容器。

**界面元素**：

| 元素 | 位置 | 说明 |
|---|---|---|
| 时钟 | `y=6`，44 号数字字体 | 目前写死 `10:24` |
| 日期 | `y=64`，14 号 | 写死 `10/20` |
| 回执横条 | `y=84`，216×28，圆角 8 | 左：意图图标；右：✓ 或 ✗ |
| 3 个意图格 | `y=122`，66×66 | ♪ 播放暂停、▶\| 下一首、田字格（更多） |
| 麦克风按钮 | `y=198`，216×56 | 青色 2px 描边，按下加粗 |

**按钮按下反馈的实现**：

```c
static void make_pressable(lv_obj_t *o, lv_event_cb_t cb, void *user_data)
{
    lv_obj_add_flag(o, LV_OBJ_FLAG_CLICKABLE);
    lv_obj_set_style_bg_color(o, COL(UI_C_PRESSED), LV_STATE_PRESSED);
    if (cb) lv_obj_add_event_cb(o, cb, LV_EVENT_CLICKED, user_data);
}
```

`LV_STATE_PRESSED` 的样式只在按下时生效，松手自动恢复。
**注意**：如果对象的常态透明度是 0（透明），按下态只改颜色还是看不见——
必须让常态也有不透明底色（返回键踩过这个坑）。

**点击分发**：

```c
on_tile_clicked()   → 有回调就 cb(kind)，否则本地假装成功
on_more_clicked()   → ui_drawer_open()（田字格是跳转，不是发指令）
on_talk_clicked()   → 同上，kind = UI_ICON_MIC
```

**回执横条更新**：

```c
void ui_main_set_result(ui_icon_t intent, bool ok)
{
    s_res_intent = intent; s_res_ok = ok;
    result_repaint();                    /* 清空两个槽再重画图标 */
    ui_drawer_set_result(intent, ok);     /* 抽屉可能开着，同步它的圆点 */
}
```

### 4.6 `ui_stage.c` —— 舞台（跟手滑动解锁）

**要解决的问题**：
用 `lv_scr_load_anim()` 切屏是**固定时长动画**，手指位移不参与控制，
滑起来像"点一下就跳过去"，没有"跟手"的手感。

**做法**：一个 240×560 的容器，上下叠两层，拖容器本身：

```
屏幕 240×280（可见窗口，把容器裁掉一部分）
└─ s_stage  240×560
   ├─ 锁屏层    y = 0    .. 280
   └─ 主界面层  y = 280  .. 560
```

`s_stage.y` 从 0 拖到 -280 的过程，就是"主界面从下方逐渐露出来"的过程。

**事件与状态机**：

```c
PRESSED      记下按下 y；lv_anim_del() 打断正在跑的吸附动画
PRESSING     dy = 按下y - 当前y；stage_set_y(-dy)，并 clamp 到 [-280, 0]
RELEASED     已拖距离 ≥ UI_LOCK_SWIPE_PX(80) → 吸附解锁；否则弹回锁屏
LONG_PRESSED 长按 1.2s → 兜底解锁
```

**为什么不用 `LV_EVENT_GESTURE`**：
那套机制依赖"滑动速度 + 默认阈值"，而 CST816 是**轮询采样、点稀疏**，
实机上经常判不出来。首尾坐标差虽然"笨"，但稳定。

**坐标归零陷阱（务必按这个顺序写）**：

```c
s_lock = lv_obj_create(s_stage);
ui_lock_build(s_lock);          /* ← 先 build */
lv_obj_set_pos(s_lock, 0, 0);   /* ← 再定位置 */
```

反过来的后果：主界面层跑到 y=0 盖住锁屏（开机直接看到主界面），
切页时两层一起被推出屏幕（黑屏）。

**对外接口**：

```c
void ui_stage_init(void);                            /* 建舞台（只调一次） */
lv_obj_t *ui_stage_screen(void);                     /* 取屏幕对象，开机 load */
void ui_stage_snap_home(void);                       /* 立即切到"已解锁"位置 */
void ui_stage_show_home(lv_scr_load_anim_t anim);    /* 从别的屏幕切回来 */
void ui_stage_lock(bool animate);                    /* 回到锁屏（预留） */
```

### 4.7 `ui_drawer.c` —— 抽屉页

**它是独立屏幕**（不是舞台的一层），因为抽屉是从主界面"滑入"的另一个界面。

**布局**：

```
y=0..44   顶部条：[< 返回键] ........ [意图图标][结果圆点]
y=97 起   3×2 指令格：
          我困了      音量+       音量−
          打开资料    查状态      语音
```

**三态反馈**（核心交互）：

```c
static void fb_repaint(ui_icon_t kind, int state)
/* state = -1 → 淡灰点（已发出，等回执）
   state =  0 → 红点（失败 或 3 秒超时）
   state =  1 → 绿点（成功） */
```

意图图标本身也有区分：等待时**暗色**，有结果后**变亮**。

**超时守卫**（为什么"常驻定时器 + 标志位"）：

```c
static void fb_timer_cb(lv_timer_t *t)
{
    if (!s_fb_waiting) return;
    if (lv_tick_elaps(s_fb_tick) < UI_DRW_FB_TIMEOUT_MS) return;
    s_fb_waiting = false;
    fb_repaint(s_fb_kind, 0);        /* 超时 → 红点 */
}
```

点击时只做三件事：`s_fb_waiting = true; s_fb_tick = lv_tick_get(); fb_repaint(kind, -1);`
收到回执时 `s_fb_waiting = false; fb_repaint(kind, ok)`。

**为什么不每次点击新建定时器**：频繁 `lv_timer_create` + 在回调里 `lv_timer_del`
容易踩"删除自身"的生命周期问题。常驻 + 标志位最稳。

**点击后不跳回主界面**（当前设计）：留在本页可以连续操作多个指令。

### 4.8 `user_link.c` —— 协议收发

**上行（发送）**：

```c
void link_send_intent(ui_icon_t kind)
{
    s_req_id = (uint8_t)((s_req_id + 1) & 0xFF);      /* 0..255 循环 */
    s_pending = kind;
    int n = snprintf(buf, sizeof buf, "OV+AI=%u,%s\r\n",
                     (unsigned)s_req_id, link_code_of(kind));
    HAL_UART_Transmit(&huart1, (uint8_t *)buf, (uint16_t)n, 100);
}
```

`link_code_of()` 是**图标 → 动作码**的映射：

| 图标 | 码 | 动作 |
|---|---|---|
| MUSIC | A01 | 播放/暂停 |
| NEXT | A02 | 下一首 |
| MOON | A03 | 我困了 |
| VOL | A04 | 音量+ |
| MUTE | A05 | 音量− |
| FOLDER | A06 | 打开资料 |
| LIST | A07 | 查状态 |
| MIC | A08 | 语音（占位） |

**下行（接收）**：中断逐字节收，遇到换行解析，**只置标志**：

```c
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART1) {
        char c = (char)s_rx_byte;
        if (c == '\n') { s_line[s_len] = 0; link_parse_line(s_line); s_len = 0; }
        else if (c != '\r') { if (s_len < LINK_LINE_MAX-1) s_line[s_len++] = c; }
        HAL_UART_Receive_IT(&huart1, &s_rx_byte, 1);   /* 重新武装，只收 1 字节 */
    }
}
```

单字节中断接收是 HAL 的标准用法：每收一个字节触发一次，
回调里必须再次调用 `HAL_UART_Receive_IT` 否则只收到第一个字节。

**必须自己补的两行**（CubeMX 生成代码里没有）：

```c
HAL_NVIC_SetPriority(USART1_IRQn, 5, 1);
HAL_NVIC_EnableIRQ(USART1_IRQn);

void USART1_IRQHandler(void) { HAL_UART_IRQHandler(&huart1); }
```

优先级 5 是刻意的：不高于 FreeRTOS 的 `MAX_SYSCALL_INTERRUPT_PRIORITY`，
以后若要在 ISR 里调用 `FromISR` 系列接口也安全。

**派发（安全上下文里改界面）**：

```c
static void link_poll_timer(lv_timer_t *t)   /* 每 30ms */
{
    if (s_ar_ready) { s_ar_ready = false; ui_main_set_result(s_pending, s_ar_ok); }
}
```

### 4.9 上电启动流程

```
main()
 ├─ HAL_Init / 时钟 / MX_*_Init（作者模板：LCD、I2C1、USART1 …）
 └─ osKernelStart()
     ├─ 硬件初始化任务 → LCD、触摸初始化
     └─ LVGL 任务
         ├─ lv_init() / lv_port_disp_init() / lv_port_indev_init()
         ├─ ui_init()            ← 我们的入口
         │    ├─ ui_stage_init()                    建舞台（锁屏层 + 主界面层）
         │    ├─ lv_disp_load_scr(ui_stage_screen())
         │    └─ link_init()                        注册回调 + 开串口中断 + 建定时器
         └─ 循环：lv_timer_handler()   ← 我们的两个 lv_timer 都在这里被调度
```

**结论**：所有界面更新都发生在 **LVGL 任务上下文**，
所以 `ui_*_set_*` 只能在同一上下文调用（中断里不能调）。

## 5. PC 端（网关）详解

### 5.1 `transport.py` —— 通道抽象

两个实现，同一套接口：

| 类 | 说明 |
|---|---|
| `SocketServerChannel` | TCP 服务端，P0 阶段无硬件联调用 |
| `SerialChannel` | 真机串口；**掉线自动重连** |

接口只有两个方法：`recv_lines()` 返回若干完整行，`send_line()` 发一行。

**串口重连的实现要点**：

```python
def recv_lines(self):
    if self._ser is None:
        if time.time() >= self._next_try:      # 每 2s 尝试
            if self._open(): print("已重连")
        return []
    try:
        n = self._ser.in_waiting
        if n: self._buf += self._ser.read(n)
    except Exception as exc:
        self._drop(str(exc)); return []        # 只标记掉线，不抛
```

### 5.2 `protocol.py` —— 帧构造与解析

- `ai_frame()` / `ar_frame()` / `ev_frame()` / `ping_frame()` / `pong_frame()` 组帧
- `parse(line)` 解析，**不认识就返回 None**（前向兼容）
- `clean_text()` 清洗 + 按字节截断

解析后是一个 `Frame` 对象，带 `req_id` / `code` / `arg` 三个属性。

### 5.3 `gateway.py` —— 主循环

```python
def run(self):
    while self.running:
        for line in self.ch.recv_lines():
            self.on_line(line)
        # 心跳：定时发 PING，连续超时判定掉线并清去重表
```

**单帧处理**：

```python
def on_line(self, line):
    frame = P.parse(line)
    if frame.kind == P.KIND_PONG: ...          # 心跳回应 → 清计数
    if frame.kind != P.KIND_REQ: return
    # ① 设备复位检测（REQ_ID 回退 / 心跳超时都清去重表）
    # ② 去重命中 → 直接回缓存
    # ③ 否则 dispatch() 执行 → 组 AR → 发回 → 存去重表
```

**双通道路由**：

```python
def dispatch(self, code, arg):
    if code in WHITELIST:          # 快通道：白名单，本地执行，不联网
        if code == "A07": return f"{time} 在线", OK
        ok, text = self.ex.execute(code, arg)
    if code == "T":                # 慢通道：自由文本 → LLM 分类
        return self.slow_channel(arg)
```

**安全设计**：LLM 的输出只能是"白名单里已存在的 code"，
即使模型被诱导注入命令，也执行不了白名单外的动作。
没配 `DEEPSEEK_API_KEY` 时自动降级到本地关键词匹配。

### 5.4 `intents.py` —— 白名单动作

```python
@dataclass
class Action:
    code: str; name: str; level: str; reply: str
    run: Callable[[str], None]
```

| 码 | 动作 | 实现 |
|---|---|---|
| A01 | 播放/暂停 | `SendInput` 发 `VK_MEDIA_PLAY_PAUSE` |
| A02 | 下一首 | `SendInput` 发 `VK_MEDIA_NEXT_TRACK` |
| A03 | 我困了 | CoreAudio 静音 + `LockWorkStation()` + 关显示器 |
| A04/A05 | 音量± | **CoreAudio** 直接设（可回读） |
| A06 | 打开资料 | `os.startfile`（ARG 空则打开桌面） |
| A07 | 查状态 | 返回时间（在 gateway 里特殊处理） |
| A08 | 语音 | 占位 |

**Executor 两种模式**：

```python
if self.dry_run:  print("[演练] ...")       # 只打印，不动系统
else:             action.run(arg)           # 真执行
```

**动态回执**：动作可以返回字符串，用它替代固定文案：

```python
def _vol_up(arg): 
    pct = round(audio_win.step_volume(+0.05) * 100)
    return f"音量已调高 {pct}%"
```

**重要约束**：网关**必须由用户自己启动**。
由受限/沙箱进程代启时，`SendInput` 会返回"成功"但输入进不了用户桌面
（详见《问题与尝试记录 §4.2》）。

### 5.5 `audio_win.py` —— 可回读的音量控制

纯 `ctypes` 走 COM，无第三方库。调用链：

```
CoCreateInstance(CLSID_MMDeviceEnumerator)
  → GetDefaultAudioEndpoint(eRender, eConsole)   取默认播放设备
  → Activate(IID_IAudioEndpointVolume)           取音量接口
  → SetMasterVolumeLevelScalar / GetMasterVolumeLevelScalar / SetMute
```

**COM 的 ctypes 调用方式**：通过 vtable 下标。

```python
def _vtbl(pobj, index, restype, argtypes, *args):
    vtbl = ctypes.cast(pobj, POINTER(POINTER(c_void_p))).contents
    fn = ctypes.WINFUNCTYPE(restype, c_void_p, *argtypes)(vtbl[index])
    return fn(pobj, *args)
```

`IAudioEndpointVolume` 的方法下标（**写错会调错函数，必须核对**）：

| 下标 | 方法 |
|---|---|
| 0/1/2 | QueryInterface / AddRef / Release |
| 7 | SetMasterVolumeLevelScalar |
| 9 | GetMasterVolumeLevelScalar |
| 14 | SetMute |
| 15 | GetMute |

`CLSID_MMDeviceEnumerator` = `BCDE0395-E52F-467C-8E3D-C4579291692E`
（记错过一次，会得到 `0x80040154` 类未注册）。

### 5.6 启动器 `run_gateway.py` + `start_gateway.cmd`

- 按 **VID_1A86** 自动枚举 CH340 串口，不用手抄口号
- 默认真执行；`start_gateway.cmd dry` 走演练
- `.cmd` 必须 **CRLF + ASCII**（LF 换行会让 cmd 拆错行）

### 5.7 `fake_watch.py` —— 无硬件联调

模拟手表发帧、自动演示多个场景、统计时延写 `latency.csv`。
在拿到硬件之前，整个协议与网关都是靠它验证的。

| 项 | 量级 | 说明 |

按 240×280 的屏幕尺寸，这个取舍是合适的。

## 结语

这个项目的技术难度不在某一处"高深算法"，而在**把一条链路从手指到系统动作全部打通，
并且每一步都可验证**。真正的工程量集中在：

1. **边界条件的处理**（设备复位后的去重、串口掉线、手势识别失败兜底）
2. **失败可见**（三态圆点、3 秒超时、动作回读）
3. **架构解耦**（UI 不知道串口；中断不碰界面；LLM 只输出白名单码）

这三点比"写了多少行代码"更能体现工程能力，也是答辩时最值得讲的部分。
