# 代码讲解：项目是怎么跑起来的

> 面向：本项目答辩自述、接手维护、以及"我想改某个东西该动哪个文件"。
> 阅读顺序建议：本文 §1 架构 → §2 一次点击的完整时序 → 再看你关心的那一段。
> 代码总量：固件侧自有代码约 1300 行 C，PC 侧约 1100 行 Python。

---

## 1. 全局架构

### 1.1 三层职责

```
┌──────────────────────────── 手表终端（STM32F411）────────────────────────────┐
│  ui_theme.h      全局常量：颜色 / 坐标 / 阈值（唯一真源）                        │
│  ui_icons.c      13 个图标：全部用矩形和线条拼，零位图、零字库                    │
│  ui_lock.c       锁屏层内容（大时钟 + 日期）                                    │
│  ui_main.c       主界面层内容（时钟/日期/回执条/3 格/麦克风按钮）                 │
│  ui_stage.c      ★ 舞台：把上面两层叠成 240×560，负责跟手拖动与吸附               │
│  ui_drawer.c     抽屉页（独立屏幕）：6 个拓展指令 + 顶部反馈圆点 + 3s 超时守卫     │
│  user_link.c     ★ 协议层：USART1 收发 OV+ 帧，中断收帧 + 定时器派发              │
└──────────────────────────────────────────────────────────────────────────────┘
                                   │ USB 串口（CH340，115200 8N1）
                                   ▼
┌──────────────────────────── PC 网关（Python）─────────────────────────────────┐
│  transport.py    通道抽象：TCP（本地联调） / 串口（真机），串口带自动重连          │
│  protocol.py     OV+ 协议：组帧、解析、文本清洗、长度限制                        │
│  gateway.py      ★ 主循环：收帧 → 去重 → 路由 → 执行 → 应答；心跳                │
│  intents.py      白名单动作：锁屏 / 媒体键 / 打开资料 + 演练模式                  │
│  audio_win.py    音量与静音：直接调 CoreAudio（可回读，不依赖按键注入）            │
│  run_gateway.py  启动器：自动找 CH340 串口 → 进 gateway.main()                  │
└──────────────────────────────────────────────────────────────────────────────┘
                                   │ Win32 API / CoreAudio
                                   ▼
                        电脑系统（网易云、锁屏、音量、资源管理器）
```

### 1.2 设计原则（三条，贯穿全部代码）

1. **界面与链路解耦**：UI 不知道串口存在。UI 只提供一个"意图回调"钩子，
   由 `user_link.c` 注册进去。想改成蓝牙/网络，只改链路层。
2. **中断只做最少的事**：串口中断只把字节攒成行、置一个标志；
   **绝不在中断里碰 LVGL**（LVGL 非线程安全），界面更新交给 LVGL 定时器。
3. **一切可验证**：动作是否真的生效，必须能读到证据（音量回读百分比、
   顶部圆点三态、3 秒超时）。原因见 [问题与尝试记录 §4](问题与尝试记录.md)。

## 2. 一次点击的完整时序（最重要的一节）

以「抽屉里点一下音量+」为例，从手指到屏幕反馈：

```
① 触摸          手指按下 → CST816（I2C1）→ 作者模板的 lv_port_indev 轮询 → LVGL indev
② 命中测试      LVGL 找到被点的对象 = drawer 里的音量+格子
③ 事件回调      ui_drawer.c: on_intent_clicked()
                  fb_repaint(kind, -1)      ← 立刻显示「淡灰点」= 已发出
④ 取回调        ui_main_get_intent_cb() → 拿到 user_link 注册的 on_ui_intent
⑤ 组帧发送      user_link.c: link_send_intent()
                  s_req_id++ → snprintf("OV+AI=%u,A04\r\n")
                  HAL_UART_Transmit(&huart1, ...)        ← 阻塞发送，几十字节
⑥ PC 接收       gateway.py: SerialChannel.recv_lines() → protocol.parse()
⑦ 去重          REQ_ID 已在表里？→ 回缓存（不重复执行）
                  REQ_ID 比上次小？→ 判定设备复位 → 清空去重表
⑧ 路由          dispatch("A04") → 命中白名单快通道
⑨ 执行          intents.Executor.execute("A04")
                  audio_win.step_volume(+0.05) → 读回音量 → 返回 "音量已调高 63%"
⑩ 应答          ar_frame(id, "OK", "音量已调高 63%") → 串口写回
⑪ 手表接收      USART1 中断：逐字节攒行 → 遇 \n → 解析 → 置 s_ar_ready 标志
                  ⚠️ 中断里只到这一步，不碰界面
⑫ 界面更新      lv_timer（30ms 一次）：link_poll_timer() 消费标志
                  → ui_main_set_result(kind, true)
                     ├─ result_repaint()      主界面回执横条更新
                     └─ ui_drawer_set_result() 抽屉顶部圆点 → 绿
⑬ 超时守卫      若 3 秒内没到第 ⑪ 步 → fb_timer_cb() 把点变红
```

**关键点**：③ 和 ⑫ 之间隔着两条硬件通路和两次进程切换，
但界面始终只认一个状态机：`淡灰(已发出) → 绿(成功) / 红(失败或超时)`。

## 3. 固件侧文件逐个讲解

### 3.1 `ui_theme.h`（89 行）—— 唯一真源

**作用**：所有颜色、坐标、尺寸、阈值都在这里。改界面外观**不该动 .c 文件**。

```c
#define UI_C_BG     0x0E1116   /* 背景近黑 */
#define UI_C_CARD   0x1B2129   /* 卡片 */
#define UI_C_ACCENT 0x35D0BA   /* 强调色（青） */
#define UI_C_PRESSED 0x2E3947  /* 按下态 */
...
#define UI_LOCK_SWIPE_PX 80    /* 上滑多少像素解锁 */
#define UI_DRW_FB_TIMEOUT_MS 3000  /* 反馈超时 */
```

**为什么重要**：设计稿是**由脚本解析这个文件生成**的（`03_design/render_c_preview.py`），
所以效果图和代码永远一致，不会出现"文档与实现不符"。

### 3.2 `ui_icons.c`（235 行）—— 13 个图标，零位图

**核心思路**：LVGL 8.2 没有填充三角形图元。要画出好看的图标，只有两条路：
引入图片（占 Flash + 需要转换工具）或用图元近似。这里选后者。

```c
static int px(int size, int num, int den) { return (size * num) / den; }
```

所有图标都按 `size` 等比缩放，内部只用两种原语：

| 原语 | 用途 | 例子 |
|---|---|---|
| `put()` = 带圆角的 `lv_obj` 矩形 | 实心块 | 麦克风话筒、列表横条、音量后板 |
| `polyline()` = `lv_line` 折线 | 线条 | 感叹号、返回箭头 |

**"台阶法"是这里的关键技巧**：用几级高度递减的矩形拼出三角形。
喇叭锥体、播放三角、对勾都是这么做的。代码里的注释说明得很清楚：

```c
/* 描边三角形在 28px 下只剩两根细线，形状感丢失 → 改成 3 级台阶 */
```

**代价**：零 Flash 占用（不含任何图片数据），零字库依赖。

### 3.3 `ui_lock.c` / `ui_main.c` —— 两个"可嵌入的层"

这两个文件**不再自己创建屏幕**，而是接收一个 parent 容器，把内容画进去：

```c
void ui_lock_build(lv_obj_t *parent);   /* 锁屏层：大时钟 + 日期 */
void ui_main_build(lv_obj_t *parent);   /* 主界面层：时钟/日期/回执/3格/麦克风 */
```

**为什么这么设计**：为了 `ui_stage.c` 能把两层叠起来做跟手滑动（见 3.4）。
如果各层都自己建屏幕，就没法让它们同时存在于一个可拖动容器里。

**主界面内容**（`ui_main_build`）：

| 元素 | 位置（来自 ui_theme.h） | 说明 |
|---|---|---|
| 时钟 | `UI_TIME_Y=6`，44 号字 | 目前是写死的 `10:24` |
| 日期 | `UI_DATE_Y=64`，14 号字 | 写死 `10/20` |
| 回执横条 | `y=84`，216×28 | 左：意图图标；右：✓/✗ |
| 3 个意图格 | `y=122`，66×66，间距 75 | ♪ 播放/暂停、▶| 下一首、田字格 |
| 麦克风按钮 | `y=198`，216×56 | 青色描边 |

**意图回调钩子**（这是解耦的关键）：

```c
typedef void (*ui_intent_cb_t)(ui_icon_t kind);
void ui_main_set_intent_cb(ui_intent_cb_t cb);   /* 链路层注册进来 */
ui_intent_cb_t ui_main_get_intent_cb(void);      /* 抽屉页取用 */
```

点击时：有回调就交给回调（真机发指令），没有就在本地假装成功（方便单独调 UI）。

### 3.4 `ui_stage.c`（178 行）—— 舞台：跟手滑动解锁

**要解决的问题**：用 `lv_scr_load_anim()` 切屏是**固定时长动画**，
手指位移无法参与控制，滑起来像"点一下就跳过去"。

**做法**：一个 240×560 的容器 `s_stage`，里面上下叠两层：

```
屏幕 240×280（可见窗口）
└─ s_stage  240×560
   ├─ 锁屏层    y = 0    .. 280
   └─ 主界面层  y = 280  .. 560
```

拖动时整体移动 `s_stage.y`，于是"手指滑 10px，主界面就露出 10px"，1:1 跟手。

**事件与状态机**：

```c
PRESSED   → 记下按下时的 y；打断正在跑的吸附动画（lv_anim_del）
PRESSING  → 实时算 dy = 按下y - 当前y；stage_set_y(-dy)，clamp 到 [-280, 0]
RELEASED  → 已拖距离 ≥ UI_LOCK_SWIPE_PX(80px) ? 吸附解锁 : 弹回锁屏
LONG_PRESSED(1.2s) → 兜底解锁（防手势识别失败被卡在锁屏）
```

**为什么不用 `LV_EVENT_GESTURE`**：那套依赖"滑动速度 + 默认阈值"，
而 CST816 是**轮询式触摸、采样点稀疏**，实机上经常判不出来。
首尾坐标差是笨办法但稳定。

**踩过的坑**（务必保留这个顺序）：

```c
s_lock = lv_obj_create(s_stage);
ui_lock_build(s_lock);          /* ← 先 build */
lv_obj_set_pos(s_lock, 0, 0);   /* ← 再定位置 */
```

因为 `lv_obj_set_pos/set_size` 写的是**样式属性**，
而 build 内部的 `lv_obj_remove_style_all()` 会把坐标一并清掉。
写反了会导致：主界面层跑到 y=0 盖住锁屏（开机直接看到主界面），
切页时两层一起被推出屏幕（黑屏）。详见 [问题与尝试记录 §2.3](问题与尝试记录.md)。

### 3.5 `ui_drawer.c`（178 行）—— 抽屉页

**布局**：独立屏幕（不是 stage 的一层），顶部条 + 3×2 指令格。

```
顶部条 y=0..44：  [< 返回键] ............ [意图图标] [结果圆点]
3×2 指令格  y=97 起： 我困了 / 音量+ / 音量− / 打开资料 / 查状态 / 语音
```

**三态反馈**（核心交互）：

```c
static void fb_repaint(ui_icon_t kind, int state)
/* state = -1 已发出等回执 → 淡灰点
   state =  0 失败/超时     → 红点
   state =  1 成功          → 绿点 */
```

**超时守卫**：常驻一个 200ms 的 `lv_timer`，靠标志判断：

```c
if (s_fb_waiting && lv_tick_elaps(s_fb_tick) >= UI_DRW_FB_TIMEOUT_MS)
        → s_fb_waiting = false; fb_repaint(kind, 0);   /* 变红 */
```

**为什么不每次点击都新建定时器**：频繁 `lv_timer_create` + 回调里 `lv_timer_del`
容易踩"删除自身"的生命周期问题；常驻 + 标志位最稳。

**设计约定**：点指令后**留在本页**，不跳回主界面（v5 需求变更）。

### 3.6 `user_link.c`（129 行）—— 协议收发

**上行（发）**：

```c
s_req_id = (uint8_t)((s_req_id + 1) & 0xFF);
snprintf(buf, sizeof buf, "OV+AI=%u,%s\r\n", s_req_id, link_code_of(kind));
HAL_UART_Transmit(&huart1, (uint8_t *)buf, n, 100);
```

`link_code_of()` 是**图标 → 动作码**的映射表（A01~A08）。

**下行（收）**：中断逐字节收，遇 `\n` 解析，**只置标志**：

```c
void USART1_IRQHandler(void) { HAL_UART_IRQHandler(&huart1); }
void HAL_UART_RxCpltCallback(...) {
    ...攒行...
    if (c == '\n') { link_parse_line(s_line); s_len = 0; }
    HAL_UART_Receive_IT(&huart1, &s_rx_byte, 1);   /* 重新武装 */
}
```

**必须自己补的两行**（CubeMX 生成代码里没有）：

```c
HAL_NVIC_SetPriority(USART1_IRQn, 5, 1);
HAL_NVIC_EnableIRQ(USART1_IRQn);
```

优先级 5 是刻意的：不高于 FreeRTOS 的 `MAX_SYSCALL_INTERRUPT_PRIORITY`，
以后 ISR 里若要调 `FromISR` 接口也安全。

**派发**：30ms 的 `lv_timer` 在 LVGL 任务上下文里消费标志，安全地改控件。

## 4. 协议设计（`protocol.py` + 固件侧格式）

**为什么用 ASCII 文本行而不是二进制**：串口调试器能直接看、人眼可读、
新增字段不破坏旧解析（前向兼容）。

| 方向 | 帧 | 说明 |
|---|---|---|
| 终端→代理 | `OV+AI=<ID>,<CODE>[,<ARG>]` | 意图请求 |
| 代理→终端 | `OV+AR=<ID>,<STATUS>,<TEXT>` | 应答（OK/ERR/BUSY） |
| 代理→终端 | `OV+EV=<EVENT>,<TEXT>` | 异步事件（预留） |
| 双向 | `OV+PING` / `OV+PONG` | 心跳 |

**设计细节**：

- `REQ_ID` 是 **uint8**（0~255 循环），用于**幂等去重**：重传不会重复执行。
- `MAX_TEXT_BYTES = 60`：屏上显示得下的量级；`clean_text()` 会去掉换行、
  按**字节**截断（不会把多字节汉字切成半个）。
- 解析不认识的行 → 返回 `None` 直接忽略（前向兼容）。

## 5. PC 侧文件逐个讲解

### 5.1 `transport.py`（212 行）—— 通道抽象

两个实现，同一套接口（`recv_lines()` / `send_line()`）：

| 类 | 用途 |
|---|---|
| `SocketServerChannel` | TCP，P0 阶段无硬件时联调用 |
| `SerialChannel` | 真机串口；**掉线自动重连**（每 2s 重试） |

**串口重连为什么必须有**：拔线、板子复位、端口被占用都会让 pyserial 抛
`SerialException`。不接住的话整个网关进程直接崩——答辩现场就翻车。

```python
try:   n = self._ser.in_waiting
except Exception:  self._drop(...)   # 只标记掉线，不抛
# 之后每 2 秒尝试 _open()，插回来自动恢复
```

### 5.2 `gateway.py`（204 行）—— 主循环

**流程**：`收行 → 解析 → 去重 → 路由 → 执行 → 应答`，循环里还做心跳。

**去重的两个边界条件**（都是实机踩出来的）：

```python
if req_id < self.last_req_id and self.dedup:
    self.dedup.clear()          # REQ_ID 回退 → 设备复位 → 作废旧表
...
if self.missed_pong > MAX_MISSED_PONG:
    self.dedup.clear()          # 心跳超时 → 设备可能复位
```

不做这一步的后果：每次重新烧录后，前几条指令会被当成"重传"而**静默丢弃**。

**双通道路由**：

```python
if code in WHITELIST:        # 快通道：白名单，本地直接执行，不联网
    ...execute...
if code == "T":              # 慢通道：自由文本 → LLM 分类 → 仍映射回白名单码
    return self.slow_channel(arg)
```

**安全设计**：LLM 只能输出**白名单里已存在的 code**，不能生成命令。
即使模型被诱导，也执行不了白名单以外的动作。

### 5.3 `intents.py`（157 行）—— 白名单动作

```python
@dataclass
class Action:
    code: str; name: str; level: str; reply: str
    run: Callable[[str], None]
```

| 码 | 动作 | 实现方式 |
|---|---|---|
| A01 / A02 | 播放暂停 / 下一首 | `SendInput` 发媒体键 |
| A03 | 我困了 | CoreAudio 静音 + `LockWorkStation()` + 关显示器 |
| A04 / A05 | 音量± | **CoreAudio** 直接设音量（可回读） |
| A06 | 打开资料 | `os.startfile`（ARG 为空时默认打开桌面） |
| A07 | 查状态 | 返回当前时间 + 在线 |
| A08 | 语音 | 预留钩子 |

**`Executor` 的两种模式**：

```python
if self.dry_run:  print("[演练] ...")      # 只打印，不动系统
else:             action.run(arg)          # 真执行
```

**重要约束**：网关**必须由用户自己启动**。由受限/沙箱进程代启时，
`SendInput` 会返回"成功"但输入进不了桌面。详见 [问题与尝试记录 §4.2](问题与尝试记录.md)。

### 5.4 `audio_win.py`（149 行）—— 可回读的音量控制

纯 `ctypes` 走 COM，无第三方依赖：

```
CoCreateInstance(CLSID_MMDeviceEnumerator)
  → GetDefaultAudioEndpoint(eRender, eConsole)     取默认播放设备
  → Activate(IID_IAudioEndpointVolume)             取音量接口
  → SetMasterVolumeLevelScalar / GetMasterVolumeLevelScalar / SetMute
```

COM 方法通过 **vtable 下标**调用（第 0/1/2 项是 QueryInterface/AddRef/Release），
所以代码里明确写了每个方法的下标常量：

```python
SET_SCALAR = 7; GET_SCALAR = 9; SET_MUTE = 14; GET_MUTE = 15
```

**收益**：动作能返回"音量已调高 63%"，而不是空话——这就是"可验证性"。

### 5.5 `run_gateway.py` + `start_gateway.cmd` —— 启动器

- 按 **VID_1A86** 自动枚举 CH340，不依赖手抄口号
- 默认真执行模式；`start_gateway.cmd dry` 走演练模式
- `.cmd` 必须 **CRLF + ASCII**（LF 换行会让 cmd 拆错行）

### 5.6 `fake_watch.py`（188 行）—— 无硬件联调

没有板子时模拟手表发帧、按场景演示、统计时延。
`latency.csv` 是它的输出（不入库）。

## 6. 一次上电的启动流程

```
main()
 └─ HAL_Init / SystemClock_Config / MX_*_Init   （作者模板：时钟、LCD、I2C、USART1…）
 └─ osKernelStart()
     ├─ 硬件初始化任务  → 初始化 LCD、触摸
     ├─ LVGL 任务      → lv_init / lv_port_disp_init / lv_port_indev_init
     │                    → ui_init()   ← 我们的入口
     │                       ├─ ui_stage_init()       建舞台：锁屏层 + 主界面层
     │                       ├─ lv_disp_load_scr(ui_stage_screen())
     │                       └─ link_init()           注册意图回调 + 开串口中断 + 建轮询定时器
     └─ LVGL 任务循环  → lv_timer_handler()  （我们的两个 lv_timer 都在这里被调度）
```

**重要**：界面的所有更新都发生在 **LVGL 任务上下文**，
所以 `ui_*_set_*` 系列函数只能在这个上下文里调用（中断里不能碰）。

## 7. 想改某个东西，应该动哪里

## 8. 资源占用概览

| 项 | 量级 | 说明 |
|---|---|---|
| LVGL 动态内存 `LV_MEM_SIZE` | 48 KB | 所有控件与样式从这里分配 |
| 刷新周期 `LV_DISP_DEF_REFR_PERIOD` | 30 ms | 约 33 FPS 上限 |
| 44 号数字字体 | 约 30~40 KB Flash | 时钟用；只含 ASCII 数字 |
| 图标 | **0 字节图片数据** | 全部图元绘制 |
| 中文字库 | **无** | 界面零文字（设计决策） |
