## 一、推荐题目

**《基于 STM32F411 的语音交互式个人助理终端设计与实现》**

英文：*Design and Implementation of a Voice-Interactive Personal Assistant
Terminal Based on STM32F411*

### 备选（按答辩风格二选一）

| 备选题目 | 适合的答辩风格 |
|---|---|
| 《嵌入式语音交互终端与上位机协同控制系统设计》 | 想突出**自动化“协同控制”**味道，弱化“个人助理”的产品感 |
| 《基于离线语音识别的便携式 PC 控制终端设计》 | 想突出**离线识别**与**控制**，避开“AI 助手”这类容易被追问大模型的词 |

**为什么不建议用“AI 智能手表”**：
老师极可能追问“大模型部署在哪、算力哪来”。本设计的大模型/识别都在 PC 侧，
终端只做交互与显示——**叫“终端 + 上位机协同”比叫“智能手表”更贴合事实，也更好答**。

## 二、设计描述（约 350 字，开题/任务书用）

本设计面向“个人 AI 便携控制助手”应用场景，研究并实现一套由**嵌入式交互终端**
与**上位机网关**协同构成的语音控制系统。

终端以 STM32F411RET6 为核心，驱动 1.69 英寸 IPS 触摸屏，基于 LVGL 图形库
构建完整交互界面，包括锁屏上滑解锁、主界面（时钟/日期/指令格/录音键）、
拓展指令抽屉、录音页（实时波形与环绕录音键的倒计时圆环、中文转写显示、
发送前确认）以及语音历史页。终端通过串口与上位机通信，采用自定义文本协议
（`OV+AI` / `OV+AR` / `OV+EV`），并实现帧同步、请求编号去重、设备复位检测与
回执超时提示等可靠性机制。

上位机网关负责语音采集与理解：使用 Vosk 离线中文模型完成语音转写，
先进行**语法约束解码**（把命令词表作为语法下发，显著降低近音字错误），
未命中时回退自由识别；再结合关键词与基于最长公共子序列的**模糊匹配**，
将自然语言映射为白名单动作码；最终调用 Windows 系统接口完成播放控制、
音量调节、打开文件、锁屏息屏等操作，并将执行回执与转写文本回显至终端屏幕。

系统针对国产开发板的实际限制做了工程优化：自研 1bpp 中文字库生成工具
（3867 个字符、81 KB 位图）解决 LVGL 内置字库缺字问题，并在 PC 端实现
按 LVGL 取位规则的字形预检，避免“烧板验证”的反复试错。

## 三、短版描述（约 120 字，用于表格/摘要框）

本设计实现一套“嵌入式终端 + 上位机协同”的语音控制系统。终端基于
STM32F411 与 LVGL 构建锁屏、主界面、录音、历史等交互界面，经串口与上位机
通信；上位机采用 Vosk 离线中文识别，结合语法约束解码与模糊匹配完成意图映射，
调用 Windows 接口实现媒体控制、音量调节、文件打开与锁屏息屏，回执实时回显终端。

## 五、可写进任务书的技术指标

| 项目 | 指标 |
|---|---|
| 显示与界面 | 240×280 IPS 触摸屏，界面操作响应 < 100 ms |
| 语音采样 | 16 kHz / 16 bit / 单声道 |
| 端到端时延 | 查询类指令 < 50 ms；系统动作类 180~200 ms |
| 指令集 | 8 类系统动作（播放暂停、下一首、锁屏息屏、音量±、打开文件、查状态、语音入口）|
| 可靠性 | 串口掉线 2 s 内自动重连；请求去重；回执超时 3 s 可视提示 |
| 中文显示 | 自研字库 3867 字符，位图 81 KB，ROM 占用约 119 KB |
| 录音限制 | 上限 10 s 自动停止，下限 0.3 s 判为误触 |
| 识别 | 词表约束 34 条短语；未命中自动回退自由识别 |

## 六、建议在文中突出的四个"工作量/创新点"

1. **分层架构的合理性**：终端不做语音理解（512 KB Flash / 128 KB RAM 跑不了任何模型），
   把识别与执行放在上位机，是资源受限条件下的正确分工，而非能力不足的妥协。
2. **三级容错识别链路**：语法约束解码 → 自由识别 → 关键词模糊匹配，
   兼顾"准"与"能自由说"，并对失败显式报错（不静默兜底假数据）。
3. **自研中文字库工具链**：从系统字体生成 LVGL 1bpp 字库 + PC 端字形预检，
   解决内置字库缺字问题，并消除"改一次字库烧一次板"的试错成本。
4. **协议可靠性设计**：帧同步、REQ_ID 去重、设备复位自动清缓存、回执超时可视反馈。

## 七、答辩可能被问到的三个问题（预备答案）

| 问题 | 回答要点 |
|---|---|
| 为什么不用大模型做意图理解？ | 已预留 T 慢通道，可接 DeepSeek 等云端/本地模型；当前用关键词+模糊匹配是因为**毫秒级、离线可用**，语音链路演示更稳定。真实可切换。 |
| 语音识别为什么不在终端上做？ | 终端 512 KB Flash / 128 KB RAM，跑不了任何声学模型；且无联网。识别质量与算力在 PC 侧，是工程取舍。 |
| 时延 180 ms 会不会太慢？ | 这部分时延来自 Windows 系统 API（SendInput/CoreAudio 同步调用），非本系统引入；查询类指令 < 50 ms。 |
