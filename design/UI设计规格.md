# 手表端 UI 设计规格（v1 草案）

> 2026-10-20 · 屏幕 240×280 · 视觉稿见 [`design/ui-mockups/`](ui-mockups/)，生成脚本 [`gen_mockup.py`](gen_mockup.py)
> 阶段：设计评审（P1 等待期） · 真机实现：Keil + LVGL 8.2

---

## 0. 为什么先做设计稿，而不是先搭 PC 仿真

| | 设计稿（本方案） | PC 仿真 |
|---|---|---|
| 今天能不能看到 | ✅ **已经看到了** | ❌ 要拉 LVGL + SDL2 + 配工程，快则半天、慢则两天 |
| 卡在哪 | 无 | GitHub 直连 8KB/s（今天已实测两次） |
| 设计决策能不能定 | ✅ 布局/配色/文案/状态机全能定 | 同样能定，但先花在环境上 |
| 真机一致性 | 中（字体是雅黑示意，真机是点阵字库） | 高 |
| 等 ST-Link 到了之后 | Keil 一编译就是**真渲染** | 还要再走一遍移植 |

**结论**：现在缺的不是渲染环境，是**设计决策**。设计稿定稿后再写 LVGL 代码，等线到货直接编译烧录——比在仿真里反复调更快。

## 1. 屏幕与网格

```
240 × 280 像素，竖屏
├─ 状态条      y = 0   … 40    （高 40，左侧 3px 色条）
├─ 主内容区    y = 40  … 244   （高 204）
└─ 操作提示条  y = 244 … 280   （高 36）
```

- **安全边距**：左右各 12px，内容不进入边缘 8px 内
- **意图网格**：3 列 × 2 行，卡片 66×58，间距 8px（起始 x=12, y=100）
- **单行文案上限**：6 个汉字（13px 字号下）；两行封顶

## 2. 配色（全部落在 RGB565 安全区，真机不会出色带）

| 用途 | HEX | RGB | 说明 |
|---|---|---|---|
| 背景 | `#0E1116` | (14,17,22) | 深色省电，对比度高 |
| 卡片 | `#1B2129` | (27,33,41) | 意图块、设置行 |
| 主文字 | `#E8EDF2` | (232,237,242) | 时间、结果 |
| 次文字 | `#8A96A3` | (138,150,163) | 日期、说明 |
| 成功/在线 | `#35D0BA` | (53,208,186) | 青 |
| 录音中/失败 | `#FF5C5C` | (255,92,92) | 红 |
| 识别中 | `#FFC24B` | (255,194,75) | 黄 |
| 处理中/确认 | `#4A9EFF` | (74,158,255) | 蓝 |

> 一律**用纯色不用渐变**：LVGL 在 240×280 上做渐变要多耗 CPU，且 RGB565 下容易出现色阶断裂。

## 4. 页面与状态（v2，2026-10-20 评审后）

### 4.1 已确认的设计决策

| 决策 | 结论 |
|---|---|
| 主题 | ✅ 深色 |
| 意图布局 | ✅ **收纳格**：主界面只放 4 个快捷入口，其余收进抽屉页 |
| 锁屏 | ✅ **上滑解锁，不放任何文字/箭头提示**（极简） |
| 确认倒计时 | ✅ 3 秒 |
| 配色（红/黄/蓝/青） | ✅ 采用 |
| 「最近结果」行 | ⏳ **待定 —— 出了 A/B 两版对比** |

### 4.2 页面栈

```
锁屏 ──上滑/KEY1──> 主界面 ──点「更多」──> 全部意图（抽屉）
                      │ │                    └──点任一格──> 触发该意图
                      │ └──长按 KEY1 / 点大按钮──> 录音中
                      └──> 设置 ──> 关于

录音中 → 识别中 →（确认）→ 执行 → 成功 / 失败 → 回主界面
```

### 4.3 十张稿对应关系

| 稿 | 页面 | 关键元素 |
|---|---|---|
| `01-home-a-无结果行` | 主界面 **A 版** | 时钟+日期 → 4 快捷格 → 大按钮 |
| `02-home-b-有结果行` | 主界面 **B 版** | 多一条「上次：已锁屏并静音」卡片 |
| `03-lock` | 锁屏 | **只有**大时钟 + 日期，零提示 |
| `04-drawer` | 全部意图 | 3×3 = 9 格（放歌/下一首/我困了/音量±/资料/状态/说话/设置） |
| `05-recording` | 录音中 | 红状态条 + 波形 + 计时 |
| `06-asr` | 识别中 | 黄状态条 + 三点动画 |
| `07-confirm` | 确认 | 识别文本 + 意图码 + 3s 倒计时环 |
| `08-ok` | 成功 | 青对勾 + 结果文字，1.5s 返回 |
| `09-error` | 失败 | 红叉 + 原因 + "指令仍可用" |
| `10-settings` | 设置 | 亮度/音量/蓝牙/固件/关于 |

### 4.4 主界面布局（两版共用骨架）

```
y=14…68    时钟 38px
y=74…94    日期
y=96…122   「最近结果」卡片     ← 仅 B 版有
y=112/132  4 个快捷格 48×48（放歌 / 我困了 / 资料 / 更多）
y=196…248  大按钮「按住说话」（216×52，青色描边）
```

- 快捷格第 4 个固定是「**更多**」（田字格图标），点它进抽屉
- 「按住说话」占满宽度的 90%，是主界面唯一的强视觉元素

### 4.3 文案规范（**状态词 ≤6 字**）

| 状态 | 文案 | 颜色 | 停留 |
|---|---|---|---|
| 录音中 | 正在录音 | 红 | 持续 |
| 识别中 | 识别中 | 黄 | 持续 |
| 处理中 | 处理中 | 蓝 | 持续 |
| 确认 | 请确认 | 蓝 | 倒计时 3s |
| 成功 | 已完成 | 青 | 1.5s 自动返回 |
| 失败 | 失败 | 红 | **3s，手动关** |

## 5. 按键映射

| 操作 | 行为 |
|---|---|
| **KEY1 单击** | 主界面：进入"说话"；确认页：确认发送 |
| **KEY1 长按（>600ms）** | 任意页面：开始录音 |
| **KEY2 单击** | 返回上一页；确认页：重录 |
| **KEY2 长按** | 关机（沿用作者原逻辑） |
| **触摸上滑** | 锁屏解锁 |
| **触摸点击卡片** | 直接触发对应意图（跳过语音） |

## 6. LVGL 实现要点 & 资源预算

| 项 | 做法 | 原因 |
|---|---|---|
| 图标 | **全部手绘几何图形**（如意图图标）或 LVGL 内置符号字体 | APP 只剩 ~50KB Flash，贴图吃不消 |
| 字体 | 中文只做 12/16/30 三档点阵 | 每加一档字库约 +20~40KB |
| 页面对象 | **只创建一次，用 `lv_obj_add_flag(HIDDEN)` 切页** | 反复 create/delete 会碎片化 128KB 堆 |
| 波形/倒计时 | 用定时器改**已存在对象**的属性 | 避免每帧创建控件 |
| 颜色 | 纯色，`lv_color_hex()` | RGB565 下渐变有色带 |
| 刷新 | 只刷变化区域（`lv_obj_invalidate_area`） | SPI 刷 240×280 全屏很慢 |

## 7. 只剩 1 件事待你拍板

**主界面要不要「最近结果」行（A 版 vs B 版）？**

| | A 版（无） | B 版（有） |
|---|---|---|
| 观感 | 更空、更透气 | 更饱满、信息密度高 |
| 好处 | 极简，时钟和说话按钮最突出 | 答辩演示后可回看"上次做了什么" |
| 代价 | 换页后看不到上次结果 | 挤掉 20px，快捷格下移 |
| 实现成本 | 0 | 一个 `lv_label` + 一个色点，约 20 行 |

我的倾向：**B 版**。理由是它是"独立可见的反馈痕迹"，答辩时你连着演示好几次，评委能顺着这一行看出"刚才那个动作生效了"。
但如果你更喜欢干净的时钟面，A 版也不亏——结果本来就会在成功页显示 1.5 秒。

**已定项（不再问）**：深色主题、收纳格布局、锁屏无提示、3 秒倒计时、红/黄/蓝/青配色。

## 9. v4 决策：全图形、零中文字库（2026-10-20）

**决定：界面不放中文**，只用①图标 ②数字 ③颜色。

| 变化 | 原来 | 现在 | 收益 |
|---|---|---|---|
| 意图格 | 图标+中文标签 | **只有图标** | 格子从 48→66，图标更大更好点 |
| 大按钮 | 麦克风+「按住说话」 | **只有麦克风** | 视觉更纯粹 |
| 「最近结果」 | 一行中文 | **左：意图图标 / 右：✓ 或 ✗** | 一眼看懂，零文字 |
| 日期 | 10月20日 周一 | **10/20** | 中文归零 |
| 状态页 | 状态词+图形 | **只有图形**（红波形/青勾/红叉） | 见 code-preview-states.png |
| **中文字库** | 需 12/16/30 三档，30~80KB | **完全不需要** | 省 Flash，省掉 lv_font_conv 一步 |

**代价与对策**：
1. **错误原因说不出**（只知道失败，不知道是断网还是超时）→ 用 PC 端 TTS 播报补足；屏上只给红叉。
2. **图标自解释性**：放歌/困了/更多 能猜，但首次上手未必懂 → 答辩时口头解释；二期可加「长按显示名称」气泡。
3. **设置页**：亮度/音量/蓝牙/固件 原本是文字列表 → 改成「图标 + 滑块/开关」，版本号挪到「关于」图标里（或先砍掉）。
4. **时间必须保留数字**：这是你列的必做功能，用 LVGL 内置 Montserrat，零额外成本。

## 8. 背景图方案（v3 新增）

**能改，但先看一个数字**：240×280 RGB565 全屏未压缩 = **131 KB**，比 128KB 的 RAM 还大，也接近整个 APP 的余量。所以**绝不能整帧缓存**，必须压缩或程序化绘制。

### 8.1 实测体积（`gen_backgrounds.py` 跑出来的真数）

| 背景 | RGB565 原始 | RLE 压缩后 | 压缩比 |
|---|---|---|---|
| `bg-1` 渐变光晕 | 131 KB | **7 KB** | 20.1× |
| `bg-2` 星空 | 131 KB | **5 KB** | 25.8× |
| `bg-3` 几何波纹 | 131 KB | **18 KB** | 7.1× |

**好消息**：深色系背景正好是 RLE 的甜区——大片同色，5~18KB 完全放得进内部 Flash。
**坏消息**：如果换成真实照片（尤其是高对比、多细节的），压缩比会掉到 1~2×，那就是 60~130KB，必须走外部 Flash。

> 说明：上面是本工具的**简易 RLE 实测**（每段 3 字节：像素 + 长度），LVGL 官方实现细节可能略有差异，但量级一致。

### 8.2 三条实现路线

| 路线 | Flash 占用 | 工作量 | 建议 |
|---|---|---|---|
| **A 程序化绘制**：LVGL 画渐变 + 色块，不放位图 | **0 字节** | 半天 | ✅ **第一版就用这个** |
| **B RLE 压缩的 C 数组**：图 → RGB565 → RLE → `static const uint8_t` | 5–18 KB | 1–2 天 | ✅ 想放图就走这条 |
| **C 存外部 SPI Flash**：FryPi 板载 W25Q128 16MB | 0（占外部） | 2–4 天 | 🟡 想做多主题切换再考虑 |

路线 C 需要自己实现"从 SPI Flash 分段读 + 注册自定义 image decoder"，是个不错的技术点，但**别在第一版做**。

### 8.3 可读性铁律（这条比好看重要）

1. **卡片不透明度 ≥ 90%**：半透明卡片压在亮背景上，小字会糊（我这版调到 230/255 才够）
2. **顶部叠 25–30% 黑幕**：保证时钟对比度
3. **背景避开高频细节**：星星可以，噪点/细纹不行（会和点阵字体打架）
4. **文字下面永远有卡片底**，不要让文字直接压在图上

### 8.4 我还没验证的部分（不装懂）

- **LVGL 8.2 的 RLE 具体 API 与 `lv_conf.h` 开关**：我只查到 LVGL 8.x 的文档目录里有 RLE 相关章节，**没能在本机验证 8.2 的确切函数名和启用宏**。落地前请对照官方 `libs/rle` 文档 + `lv_conf.h` 确认。
- **官方转换入口**是 `lv_img_conv` 工具，它生成的格式 LVGL 一定能读——**比自己手搓 RLE 稳**。
