# 炸鸡派 FryPi 作毕设底座的评估（对比 OV-Watch）

> 评估日期 2026-10-19 · 仓库 [No-Chicken/FryPi](https://github.com/No-Chicken/FryPi)（master，最后推送 2026-05-26）· 手册 [no-chicken.com/content/FryPi](https://no-chicken.com/content/FryPi/intro.html) · 教程与手表共用同一套 [BV1pfRCBPEdC](https://www.bilibili.com/video/BV1pfRCBPEdC/)
> 硬件信息以仓库 `1.hardware/` 里的 **BOM 与原理图 PDF** 为准（立创开源页本次被 CloudWAF 拦 418，未采用）。

## 一、结论

**比 OV-Watch 更适合当"毕设底座"，但形态和选题必须换。**

FryPi 把 OV-Watch 里最劝退的三件事（双层板手焊、机械结构、多传感器一致性）一次性砍掉，换来"到手即用 + 全 IO 引出 + 板载 16MB SPI Flash"；代价是**板载一个传感器都没有、没有电池电路、没有外壳**，演示形态从"能戴的手表"退化成"板卡 + 一块屏"。

所以用它做毕设，正解不是"再做一个手表"，而是 **买核心板 + 自己画一块传感器底板**：核心板当买来的平台，底板和代码主体当你的工作量。这恰好把上一份报告里最要命的合规风险（"哪部分是你做的"）变成了加分项。

## 二、核到的硬件事实（来自 BOM）

| 项 | 内容 | 依据 |
|---|---|---|
| MCU | **STM32F411RET6TR**，LQFP-64，512KB Flash / 128KB SRAM，100MHz | BOM 第 20 项；`3.reference_sheet/DS10314-STM32F411xE datasheet.pdf` |
| 存储 | 板载 **W25Q128JVSIM（16MB SPI NOR Flash）** —— 不是选配，BOM 里是标准物料 | BOM 第 22 项 |
| USB | 两个 Type-C（`TYPE-C 16PIN 2MD`）+ **CH340N** USB-TTL | BOM 第 21、23 项 |
| 电源 | **XC6206P332MR**（3.3V LDO），**无充电电路、无电池座**（BOM 无 TP4056/充电 IC）→ 只能 USB 供电 | BOM 第 19 项 |
| 时钟 | 25MHz HSE + **32.768kHz RTC** 晶振 | BOM 第 24、25 项 |
| 人机 | 2 个贴片按键 + 4 颗 LED + **18P FPC 屏座**（AFC01-S18FCA-00） | BOM 第 9、10、18、26 项 |
| 扩展 | **2×26P 排针 ×2** + 4P 排针（IO 全部引出） | BOM 第 7、8 项 |
| 屏幕 | **P169H002-CTP** = ST7789V3A 驱动 + **HSD017BPW1-C-T（1.69 吋 IPS）**，触摸 **CST816T** | `3.reference_sheet/P169H002-CTP手册资料/`（ST7789V 规格书 + CST816T 规格书都在） |
| **传感器** | **一个都没有**（BOM 内无任何 sensor） | BOM 全表 26 项 |
| 摄像头扩展板 | `exCam` 板只有 2×26P 母座 ×2 + 18P FPC 座 + 4P 母座 + LED + 上拉电阻 —— **纯转接板，也无传感器** | `BOM_Sch_exCam_2024-02-16.xlsx` |

**三个直接影响选题的事实：**

1. **16MB W25Q128 是白送的大礼包。** 上一份报告里"OV-Watch 512KB Flash 装不下 A/B 双分区、OTA 做不了回滚"这个死结，在 FryPi 上被这块外挂 Flash 解开了——镜像可以放外部 Flash 做 staging + 回滚。而且我发现 OV-Watch 的代码里**完全没有 W25Q/SPI Flash 驱动**（只有内部 Flash HAL），所以这个方向是真正的空地。
2. **没有电池电路。** 想沿用"低功耗"方向，得自己搭电池 + 充电 + µA 级测量，工作量比手表那边多一层。
3. **模板工程里带 USB MSC 类**（`1.Basic/0.template/Middlewares/.../Class/MSC/`），配合板载 W25Q128，与 README 所述"插 USB TypeC 会枚举成一个 U 盘"对得上——这给你一个现成的"数据搬运"通路。

仓库状况：**GPL-3.0**，388★ / 79 fork，issue **全量仅 4 条**（open 3），**无 release**，最后推送 2026-05-26。→ 社区比手表小一个量级，遇到问题基本只能问作者或进群。

**价格**：作者本人在演示视频 [BV1u2421F7kf](https://www.bilibili.com/video/BV1u2421F7kf)（2024-02-17）简介里自述"成本在 50 元以内"（指板子 BOM，**不含屏幕**）；仓库 issue #4（2025-08-11）里有位海外用户称"淘宝店约 ¥79"，作者未确认具体型号。屏幕 P169H002-CTP 单独计价。**具体成交价需你自行查电商核实**。

## 三、例程家底（这是它真正的价值）

- **Basic 0–9**：template（含 CMake 版 + 链接脚本）、GPIO、USART、TIM、**PWM（含互补输出 + 死区）**、ADC、SPI、I2C、USB-CDC、LCD+触摸
- **Advanced 0–8**：FreeRTOS 五连（模板/信号量/互斥/定时器/钩子）、**CubeAI**、MNIST 手写数字（python_codes + stm32_codes）、**MLX90640 热成像手势识别**（Keras 训练 → .h5 → 部署）、VS Code EIDE、**Simulink 硬件在环（HIL）**、LVGL 手表（`LVGL_template` + `OV_Watch` 两份）、**IAP_F411（BootLoader + Ymodem）**、OV2640 识别
- 手册站另有独立成体系的 **RTOS 基础 9 篇 + LVGL 基础 5 篇**，比看视频回放更适合查资料

⚠️ 注意：`6.LVGL-SmartWatch/OV_Watch` 是把手表代码整份搬过来的，**13 个 BSP 目录一个没删**（EM7028 / LSM303 / SPL06 / MPU6050 / KT6328 都在），但 FryPi 板上并没有这些传感器。也就是说：**UI 能直接跑，真实传感器数据必须自己接**——这既是它的短板，也正是你的增量入口。

## 四、和 OV-Watch 怎么选

| 维度 | OV-Watch（成品手表） | FryPi（核心板） |
|---|---|---|
| 上手速度 | 买成品后中等；自己打板则很慢 | **最快**（上机测试：插串口、L2 闪、按键切模式） |
| 焊接风险 | 高（双层板 + 0603 + 磁吸 + FPC） | **低**（模块级，底板可用 0805 + 插座） |
| 传感器 | 齐（6 类） | **零**，全要自己接 |
| 演示冲击力 | **强**（能戴在手上） | 中（板卡 + 屏，需自己做外壳补救） |
| 硬件自主设计空间 | 小（几乎照抄） | **大（自画底板就是你的硬件章节）** |
| OTA 回滚 | 做不了（512KB 无余量、无 SPI Flash） | **能做（板载 16MB）** |
| 自动化专业的味道 | 偏"嵌入式 UI" | **可走 Simulink HIL / 数字电源 / 电机控制**（PWM 互补死区 + ADC + HIL 例程都现成） |
| 社区 | 2560★，issue 17 | 388★，issue 4 |
| 合规风险 | 高（全流程视频 + 全量代码） | **中**（换成小项目后"整份照抄"的诱惑小很多，但 MLX90640 手势例程同样已开源） |

## 五、用 FryPi 的三条可选路线

**路线 1（最推荐）· 自制传感器底板 + 边缘 AI**
核心板买成品 → 自己画一块底板（I2C/SPI 传感器 + 电池 + 充电 + 电流采样点）→ 自写 BSP → FreeRTOS 多任务 → 自采数据集做 CubeAI 分类。硬件、软件、算法三章都有你的东西，合规最干净。
风险：画板打样要 1–2 周，得有第一次就把板子画对的自觉（参考 `1.hardware/` 的 SCH PDF 学画法）。

**路线 2 · W25Q128 上的可回滚 OTA**
在 `7.IAP_F411` + `Ymodem` 基础上做：镜像校验（CRC/签名）、断点续传、A/B staging 到外部 Flash、断电恢复、失败自动回滚。这是**在 OV-Watch 上物理做不到、在 FryPi 上刚好能做**的方向，答辩讲起来清楚，代码全是增量。
风险：BootLoader 逻辑一旦写崩，容易把自己锁在板外，**务必先留好 SWD 救砖预案**。

**路线 3 · Simulink HIL + 控制算法（最像自动化毕设）**
用 `5.simulink-Co-develope` 铺好的在环链路，做"控制算法 → 代码生成 → 板卡在环验证 → 实测响应曲线"。配 `4.PWM` 的互补死区例程，可以做小型数字电源/电机驱动。
风险：**需要 MATLAB/Simulink + STM32 硬件支持包授权**，学校没校园授权就别碰；版本兼容也容易卡。

**不建议**：买板 → 跑 `6.LVGL-SmartWatch` → 换个表盘交差。那只是把"复刻手表"换成"复刻开发板例程"，问题一模一样，还丢掉了手表那点演示优势。

## 六、用 FryPi 的坑，按疼的程度排

1. **零传感器 + 零电池**：所有外设都要你选型、画板、写驱动。这正是工作量所在，但也是 10 周里最容易失控的地方。
2. **MATLAB 授权**（仅路线 3）：没有校园授权就没这条路。
3. **社区小**：issue 只有 4 条，等于没有前人踩坑记录；手册和例程本身质量不错，但没有"搜一下就有答案"的生态。
4. **演示形态弱**：一定要配外壳（3D 打印一个桌面支架/仪表壳），并准备录屏。
5. **MLX90640 模块成本**（价格待查，通常不便宜）+ 该例程已开源，照跑就是复刻。
6. 仍是 **GPL-3.0**，规则同上一份报告：保留 LICENSE、README 写清 fork、论文里写明"基于开源项目二次开发，本文贡献为……"。

## 七、我的建议

**买 FryPi 核心板，走路线 1 打底、路线 2 加分，把题目从"智能手表"改成"自研传感器终端的边缘智能与可靠升级"。**

理由三点：
- 核心板买来就通，把最不可控的焊接风险彻底移出关键路径；
- 底板是自己画的，"硬件自主设计"这一章名正言顺，合规上再没软肋；
- W25Q128 上的可回滚 OTA 是**这个平台独有、且开源代码里完全没写**的方向，答辩问"你做了什么"时有干净利落的答案。

一句话：手表是"看起来最像成品"，FryPi 是"看起来最像你的作品"。毕设要的是后者。

## 八、附：这块板子的"AI 能力边界"

问题不是"能不能接 AI"，而是"是哪一种 AI"。三条路差别极大：

**A 板上离线推理（推荐，可行）**
用 X-CUBE-AI / CubeAI 把模型转成 C 代码跑在 F411 上。作者的两个例程就是天花板实证：CubeAI 例程是 3 层 MLP（10-5-1）拟合 sin(x)；MNIST 是 `Conv2D(3@5×5) → MaxPool → Dense(32) → Dense(16) → Dense(10)`，**按 README 给出的结构算约 1.7 万参数**，喂 30×30×1 的图。
→ 结论：**几千到两万参数级的小网络**是这块板子的舒适区。适合 6 轴 IMU 的时序分类（手势/动作识别，1D-CNN）、振动/异常检测、简单字符识别。再大就装不下。

**B 联网调云端大模型（不推荐）**
FryPi **没有 WiFi**，要自己加 ESP-01S/ESP32 模块走 UART。但 ESP-01S 只有 AT 指令、**不带 TLS**，云端 HTTPS 大模型 API 直连不了，得自己搭网关转发。再加它和你既有的火灾报警项目思路重复，答辩容易被打成"调 API"。

**C 语音唤醒（可行但吃紧）**
需要加 I2S 数字麦（如 INMP441 一类）→ MFCC 特征 → 小 CNN。F411 有 I2S 外设，但 128KB RAM 下 MFCC 缓冲 + 模型激活 + LVGL 帧缓冲三者会抢内存，属于"能做但要精打细算"。

**内存账要先算**：128KB SRAM 里要装 RTOS 11 个线程栈（参考手表工程 128B×1~24）、LVGL 绘制缓冲（240×280 RGB565 若用 1/10 屏部分缓冲约 13KB，估算）、模型权重（放 Flash 不算 RAM）+ 激活缓冲。**先算账，再选模型**，这是这个平台最容易翻车的地方。

## 十、附：不买 FryPi，改买通用开发板行不行

**行，而且合规上最干净——但要选对型号，别踩 F103 蓝丸这个坑。**

四条路横向对比：

| 方案 | 硬件合规 | 前期耗时 | 内存/Flash | 例程与文档 | 备注 |
|---|---|---|---|---|---|
| **F103C8T6 蓝丸（最常见最便宜）** | 最干净 | 短 | **64KB Flash / 20KB RAM，无 FPU** | 少 | ❌ **跑不动 LVGL 8.x + 中文字库 + AI**，别选 |
| **F411 最小系统板（如 WeAct 那类）** | 最干净 | 中（+1~2 周） | 512KB / 128KB，有 FPU | 可平移作者 F411 代码（改引脚） | ✅ 性价比最高的"全自主"方案 |
| **FryPi 核心板** | 中（GPL 开源硬件） | **最短** | 同上 | **5950 个文件的例程 + 手册 + 视频** | 买到的是"时间"，不是板子 |
| **Nucleo-F411RE（ST 官方）** | 干净 | 短 | 同上 | ST 官方例程最全，**CubeAI 官方示例都基于 Nucleo** | 贵一些、体积大；**板载 ST-Link**，省一个调试器；学校实验室常有 |

选型的三条硬约束（比品牌重要）：

1. **Flash ≥ 256KB、RAM ≥ 64KB**——LVGL 8.x + 中文点阵字库 + 小模型，64KB/20KB 的 F103 直接出局。**这是最重要的一条，很多人被"蓝丸才十几块"带偏。**
2. **必须有 FPU**（Cortex-M4F 起）——浮点 LVGL 渲染和神经网络推理都吃它，F103 的 M3 没有。
3. **要有 32.768kHz LSE 晶振**，否则 RTC 精度差、低功耗专项没得做（买前看实物图确认，很多最小系统板不焊）。

换最小系统板省下的 vs 多花的：

- **省下**：几百块板子钱；彻底摆脱"别人的开源硬件"这层顾虑（软件引用 GPL 代码仍要注明）
- **多花**：板级 BSP 与引脚/时钟重配约 3–7 天、LVGL 移植约 2–4 天，合计 **1.5–2 周**——在 10 周预算里是 15–20%
- **额外要买**：ST-Link V2（烧录调试必需）、屏（ST7789 SPI，**别用长杜邦线**，240×280 高速刷屏会花屏，建议短排线或自己画转接小板）、传感器模块、若要做可回滚 OTA 再加一块 W25Q 模块（SPI 模块，好加）

**结论**：动机是"省钱 + 硬件全自主" → 选 **F411 最小系统板**，别选 F103；动机是"10 周内稳出成果" → FryPi 那几十块买的是 5950 个文件的例程和一套手册，很值。**最不建议的是"蓝丸 + 杜邦线"组合**：便宜是真便宜，内存和信号完整性会把你拖死。

## 十一、附：就选 STM32F411CEU6 这块板子

**这是"自己买板"路线里的最优解，不是将就。**

理由：**F411CEU6 正是 OV-Watch 用的那颗芯片**（仓库里 `Software/IAP_F411/MDK-ARM/DebugConfig/IAP_F411_STM32F411CEUx.dbgconf` 就是佐证），512KB Flash / 128KB SRAM / Cortex-M4F（有 FPU）/ 100MHz，上一节那三条硬约束全部满足。而且**同款芯片意味着参考代码最容易平移**——比 FryPi 的 F411RET6（LQFP64）更贴近手表工程，外设映射基本一致，改引脚即可。

| 芯片级规格（DS10314） | 值 | 对你的意义 |
|---|---|---|
| 内核 | Cortex-M4F，DSP + **FPU**，100MHz | LVGL 浮点渲染、神经网络推理都要它 |
| Flash / SRAM | **512KB / 128KB** | 够跑 RTOS + LVGL + 小模型 |
| 封装 | **UFQFPN48** | ⚠️ 比 F411RE 的 LQFP64 **少一批引出脚**，画底板前必须先排引脚冲突 |
| 外设 | USB OTG FS、≥3 路 USART + 2 路 UART、多路 SPI/I2C、2×I2S、16 通道 12bit ADC、RTC | 屏 / 传感器 / 蓝牙 / 数字麦全够 |

**三条约束会原样继承（别忘）**：
1. **A/B 双分区仍然做不了**（512KB 里 APP 就占 390KB）→ 想做得自己加一块 **W25Q128 SPI 模块**，好在模块化，比在手表板上加容易得多。
2. **128KB RAM 要算账**：RTOS 栈 + LVGL 部分缓冲 + 模型激活三者抢内存。
3. **512KB Flash 也别浪费在资源上**：中文字库、图片建议丢到外部 SPI Flash，程序里按需读——这本身就是一个能写进论文的工程点。

**买板前必须确认的三件事**（很多卖家图看不清，问清楚）：
- [ ] 板载 **25MHz HSE** 主晶振（做 USB 时钟和 100MHz 主频要用）
- [ ] 板载 **32.768kHz LSE** 晶振 —— **做 RTC / 低功耗专项的必需项，很多最小系统板不焊**
- [ ] USB 口是否直连 PA11/PA12（若只做了 USB 转串口，就得另买一个 USB-TTL 做调试口）

**最小采购清单**（都买模块，别买裸芯片）：F411CEU6 核心板、ST-Link V2、ST7789 SPI 屏（240×280，带触摸的最好，触摸多是 CST816 系列 → 与参考代码同款）、MPU6050 模块（最便宜的 6 轴，资料最多）、W25Q128 SPI 模块、传感器按你后面定的功能再加。心率建议走 **MAX30102** 而不是 EM7028——后者资料极少，作者自己都先自写算法又改回官方库。

**最大的红利**：可以直接把 `Software/IAP_F411`（BootLoader）和 `Software/OV_Watch`（APP）两个工程拿来做**引脚重映射**，省掉自己从零搭 FreeRTOS + LVGL 骨架的 2–3 周。代价是必须保留 GPL-3.0 声明、README 写清来源。

⚠️ 实操顺序：**先用模块 + 短杜邦线把屏和传感器点通，再决定要不要画底板**。别一上手画板——引脚冲突和信号完整性会在打样后才暴露，那时的返工最贵。

### 补：买现成 F411CEU6 核心板的三个注意点

1. **优先选"带 SPI Flash"的 SKU**（常见 4MB/8MB 版本）。多花几块钱，一次性解决 A/B staging 与字库/图片存储——比事后飞线焊一块 W25Q 模块省事得多。
2. **这个价位适合买两块**。二三十块的东西，烧坏了或焊坏了不至于让整周进度停摆，备用板是本科生最便宜的保险。
3. **⚠️ 现成板做不了"干净的"低功耗测量**：板载 LED、LDO 静态电流、USB 上拉/分压电阻都会污染 µA 级读数。若选低功耗专项，要么测量时把 LED 等负载断开、直接从 LDO 输出端串电流表，要么就把低功耗部分放到自画的底板上做——**这一点决定了"低功耗"和"用现成板"两个选择天然有冲突**，选题时要一起想。

## 十二、决策收口：外貌党路线（选 OV-Watch 成品）

**"好看"是正当理由，不是虚荣。** 答辩评分里"作品完整度 / 演示效果"确实是独立一项，一块能戴在手上的手表和一块插着杜邦线的开发板，评委的第一印象差距是真实的。所以如果最终倾向 OV-Watch，我支持——但要先过**两道关卡**，任一不过这条路就走不通：

**关卡 1｜买得到成品吗？**
作者淘宝店存在，但我没取到商品页价格与库存。**买不到成品就必须自己打两块双层板 + 0603 + 磁吸焊盘**，那条路的焊接风险我在原报告里已经标红。这是第一优先要确认的事，它决定整条路成立与否。

**关卡 2｜导师认不认"买成品"？（基本通过，但需落实）**
已初步确认老师没要求硬件必须自己焊接 → 这道关基本过了。但两件事要补：
- **"好像没要求"要落成明确答复**，最好在开题沟通里留痕（微信/邮件），尤其"如何认定我的工作量"这句要问出来。
- **"不要自己焊" ≠ "可以复刻"**。老师的潜台词通常只是"焊接不是考核重点"，考核重点会转到**你的设计贡献**上。所以工作量必须从硬件挪到软件/算法，且开题报告里就要把增量写死。
- 论文的"硬件设计"章节要相应改写：不写"我设计了电路"，改写**"平台选型论证 + 传感器数据链路分析 + 二次开发接口设计 + 功耗/资源预算"**，这是站得住的做法，但章节结构最好先给导师过一眼。

**两关都过 → 增量就要锁"不动硬件"的方向**（成品别拆，拆壳有弄坏的风险，而且没有备件）：

| 优先 | 增量 | 为什么适合成品路线 |
|---|---|---|
| 1 | **MPU6050 边缘手势识别（CubeAI + 自采数据集）** | 传感器板上就有，一根线都不用接；代码 100% 自写 |
| 2 | **心率/血氧算法改进**（滤波 + 自适应阈值 + 与官方库对比） | 血氧是作者公开未做的空缺；能做出"准确率提升"的量化指标 |
| 3 | UI 体系（页面栈重构/主题引擎） | 只加分，不宜当主菜 |

不推荐在这条路上做：**低功耗专项**（要串电流表、拆壳动硬件）、**A/B 双分区 OTA**（512KB 物理装不下）、**加 WiFi 接大模型**（板上无 WiFi，要飞线拆壳）。

**一句提醒**：外观优势只在"增量说得清"时才成立。一块漂亮的手表配一个说不清的贡献，比一块朴素的开发板配一份扎实的设计更危险——前者会让人直接问"这是你做的吗"。

**如果关卡 1 不过**（买不到成品），还有第三条路——**把焊接外包出去**：

仓库 `Hardware/` 里有 `OV-Watch_V2.4_LCProject_2024-05-25.epro`（立创 EDA 工程）+ `Gerber_Core/Gerber_Back` + `SCH_Core/SCH_Back` 的 PDF。用立创 EDA 打开 `.epro` 就能**直接下单打样 + SMT 贴片**，把 0603 那一堆交给贴片线。剩下真正难焊的（磁吸触点、FPC 座、排线）再自己上，或者请实验室/学长代手。费用需在立创下单页面按实际器件估算，我没查到可靠报价，别按我给的任何数字做预算。

这条路的价值：**"老师不要我自己焊"这句许可，正好用来买 SMT 服务**，比硬着头皮手焊靠谱得多。

## 十三、FryPi 能不能支持"语音"：能，而且引脚够（实证）

我从仓库 `images/frypi-pin-map.jpg` 把引脚图逐个读了出来。这是一块 **2×13 + 2×13 = 52 针全引出**的板子，结论很干净：

**已被占用的（丝印标了网络名）**：
`LCD_DC=PC12`、`LCD_CS=PD2`、`LCD_RST=PB4`、`LCD_CLK=PB3(SPI1_SCK)`、`LCD_SDA=PB5(SPI1_MOSI)`、`LCD_BL=PA15`、`TP_SCL=PB6(I2C1_SCL)`、`TP_SDA=PB8`、`KEY=PA0`、`LED2=PC13`、`USART1_TX=PA9`、`USART1_RX=PA10`（接 CH340N）、`USB_DM=PA11`、`USB_DP=PA12`

**空闲且已引出的（一大把）**：
`PA1–PA8`（其中 PA8=I2C3_SCL，丝印标 MLX SCL）、`PC0–PC11`（PC9=I2C3_SDA，丝印标 MLX SDA）、`PB0/PB1/PB2/PB9/PB10`、**`PB12/PB13/PB14/PB15`**

### 关键结论：I2S2 三根脚全部空闲

| I2S2 信号 | 引脚 | 状态 |
|---|---|---|
| WS（左右声道时钟） | **PB12** | ✅ 空闲、已引出 |
| CK（位时钟） | **PB13** | ✅ 空闲、已引出 |
| SD（数据输入） | **PB15** | ✅ 空闲、已引出 |

- **I2S3 用不了**：I2S3 的 CK/SD/WS 正好落在 PB3/PB4/PB5，全被 LCD 占了
- 所以走 **I2S2 做数字麦输入**
- 而且板载 **25MHz HSE**，I2S 时钟精度好（OV-Watch 没有 HSE，只能走 HSI）

### 顺带：FryPi 的传感器接口也是空的

`PA8/PC9` 是 **I2C3**，丝印标着 `MLX SCL/MLX SDA`（作者本是留给热成像模块的），空闲没用 → 你外挂 MPU6050 / MAX30102 / AHT21 这类 I2C 模块，直接接这两个脚，**不与触摸屏抢 I2C1**。

### 还有两个对毕设很实在的好处

1. **板载 CH340N + Type-C → 可以 USB 直连电脑串口**，根本不需要蓝牙。带宽从"几 KB/s"变成"随便传"，音频流、调试信息、日志全都能过；也省掉蓝牙配对/掉线重连这一整类坑。
2. **板载 W25Q128（16MB）** → 音频缓冲、字库、图片、A/B 镜像都有地方放，不用心疼 512KB。

### 但代价也要说清楚

| 缺什么 | 影响 |
|---|---|
| **零传感器** | 翻腕唤醒、心率这些要自己买模块接上（I2C3 有空，接起来不难） |
| **无电池/充电电路** | 只能 USB 供电，做不了"戴在手上"的续航演示 |
| **无外壳** | 得自己 3D 打印，成品形态是"板卡 + 屏"，不是手表 |
| **屏要另配** | 18P FPC 座（AFC01-S18FCA-00），或用普通 SPI 模块屏飞线 |

**一句话**：FryPi 是"**语音 + USB 直连 + 大 Flash**"的解法，代价是丢掉"手表形态"；OV-Watch 是"**手表形态 + 传感器齐全**"的解法，代价是麦克风这条路被封死（详见功能方案文档第十一节）。**两个优势互斥，10 周只够选一个。**

## 十四、exCam 扩展板到底是干什么的

从 `1.hardware/SCH_exCam_2024-04-09.pdf` 和 BOM 看，它是一块**纯载板 + 接口转接板**，本身没有任何芯片和传感器：

| 上面有什么 | 用途 |
|---|---|
| **2× 2×26P 母座**（U3/U4） | 插 FryPi Core 板的两排 2×26 排针，把 Core 变成"三明治"结构 |
| **18P FPC 座** | 接 1.69″ 屏 **P169H002-CTP**（LCD 六根 + 触摸四根），带 2× 4.7K 的 I2C 上拉 |
| **1×4P 母座 H2（丝印直接标 `MLX90640`）** | 热成像模块的 I2C 接口（3V3/GND/SCL/SDA） |
| **OV2640 并口** | D0–D7 + PCLK + VSYNC + HREF + PWDN + RST + SCCB(SCL/SDA) + FLASH_CTL |
| USB_DP/DM、USART1、PC6 等 | 顺手引出来，方便夹表笔/接调试线 |

**核心作用就俩**：① 机械上把屏和摄像头固定到正面，不用杜邦线吊着；② 把"要插模块的地方"做成标准座（就是作者演示动图里那个"Core 立起来、屏朝前、摄像头朝上"的形态）。

### 对你的选题：**不用买**

你现在的方向是"手表形态 + 意图通道"，**不需要摄像头**。而且这块板还有两个真实的坑：

1. **OV2640 例程是空的**：`2.software/2.Advanced/8.OV2640-recognition/readme.txt` 全文只有两行——`Last updata: 2023.11.19` 和 `todo`。**作者自己没做完。**
2. **F411 跑不动真图像识别**：QVGA RGB565 = 320×240×2 = **150KB**，而整片 RAM 只有 128KB → 只能小窗口/灰度降采样，或干脆只做"采集 + 转发给 PC"。
3. 反过来看就明白了：**MLX90640 只有 32×24 = 768 像素**，数据量小到 F411 完全吃得下——这就是为什么"热成像手势识别"能跑起来，而 OV2640 只剩一个 `todo`。

所以：**如果哪天你想做"AI 看东西"，正确入口是 MLX90640（插 H2 那个 4P 座），不是 OV2640。** 但那条路作者的例程已开源，照跑就是复刻，慎入。
