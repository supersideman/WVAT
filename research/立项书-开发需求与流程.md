## 1. 项目定义

### 1.1 定位
**"它不是智能手表，是戴在手上的 AI 遥控器。"**

目标场景：用户手头在干别的事，不看屏幕，按一下手表说一句话，任务在电脑上被完成，结果通过屏幕回执。

### 1.2 三端分工（系统边界，必须写进论文）

| 角色 | 承担 | **不承担** |
|---|---|---|
| **终端**（手表） | 语音采集、意图触发、状态显示、本地降级指令 | 不联网、不做语义理解、不执行 |
| **代理**（PC 网关） | ASR、意图解析、白名单调度、执行、语音播报 | 不做界面渲染 |
| **认知**（云端 LLM） | 模糊语义 → 结构化动作 | **绝不直接执行任何操作** |

### 1.3 开源合规声明（开题就要写）
- 软件参考 **[OV-Watch](https://github.com/No-Chicken/OV-Watch)（GPL-3.0）** 与 [FryPi](https://github.com/No-Chicken/FryPi)（GPL-3.0）
- 论文中明确写："本课题基于上述开源项目二次开发，本文贡献为：通信协议扩展、双通道意图路由、分级确认机制、多模态反馈、PC 端代理实现……"
- 保留原 `LICENSE`，README 写清 fork 来源；增量代码落在**自己新建的文件/模块**上

## 2. 硬件方案

### 2.1 为什么是 FryPi（决策依据）

需求推导链：**语音是主线** → 需要麦克风 → 需要空闲 I2S 引脚 → OV-Watch 板空闲 IO ≤5 个且未引出 → **只有 FryPi 可行**。

引脚实证（从仓库 `images/frypi-pin-map.jpg` 逐脚读出）：

| I2S2 信号 | 引脚 | 状态 |
|---|---|---|
| WS | **PB12** | ✅ 空闲、已引出 |
| CK | **PB13** | ✅ 空闲、已引出 |
| SD | **PB15** | ✅ 空闲、已引出 |

另：板载 **25MHz HSE**（I2S 时钟准）、**32.768kHz LSE**（RTC 可用）、**W25Q128 16MB**（资源/缓冲）、**CH340N + Type-C**（USB 直连电脑，音频流才传得动）。

### 2.2 采购清单

**第一批（马上买）**
| 件 | 说明 |
|---|---|
| FryPi 核心板 | 同系列例程可参考 |
| 屏 | 1.69″ P169H002-CTP（ST7789 + CST816T，18P FPC）**或** 普通 ST7789 SPI 模块屏（240×280） |
| I2S 数字麦 | INMP441 / ICS-43434 一类 |
| ST-Link V2 | 烧录调试必需 |
| 杜邦线（短） | ⚠️ 别用长线接 SPI 屏，会花屏 |

**第二批（阶段 3 形态再做）**
LIS3DH/MPU6050（翻腕唤醒）、硬币振动马达 + S8050 + 续流二极管、锂电池 + TP4056 充电模块、3D 打印外壳、表带

### 2.3 硬件红线（血泪经验）
1. **屏是最脆的** → 先做"裸板测试台"，通全部功能再谈装配
2. **锂电必须带保护板**，极性接反烧稳压器；首次上电串限流
3. **别用长杜邦线接 SPI 屏**（240×280 高速刷屏会花屏，容易误判成代码 bug）
4. 现成板做不了"干净的"低功耗测量（LED/LDO/上拉污染 µA 读数）

## 3. 系统架构

### 3.1 数据流

```
┌──────────────┐   I2S 采集    ┌────────────────┐  USB/蓝牙  ┌─────────────────┐  HTTPS  ┌──────────┐
│  麦克风       │ ────────────> │  FryPi (F411)  │ ────────> │  PC 网关(Python) │ ──────> │ DeepSeek │
│              │               │  FreeRTOS+LVGL │ <──────── │  ASR→路由→执行    │ <────── │          │
└──────────────┘               └────────────────┘  状态回传  └─────────────────┘         └──────────┘
                                    屏幕反馈                       语音播报 + 镜像窗
```

### 3.2 双通道意图路由（核心设计）

```
         ┌── 快通道：白名单命中 ──> 本地执行（毫秒级、断网可用、结果确定）
语音意图 ─┤
         └── 慢通道：白名单未命中 ─> LLM 理解 / 转交 agent（秒级、能力上限高）
```

### 3.3 通信协议（ASCII 文本行，`\r\n` 结尾，UTF-8 载荷）

| 方向 | 帧 | 含义 |
|---|---|---|
| 终端→代理 | `OV+AI=<REQ_ID>,<CODE>[,<ARG>]` | 发起意图 |
| 代理→终端 | `OV+AR=<REQ_ID>,<STATUS>,<TEXT>` | 应答（TEXT ≤60 字节） |
| 代理→终端 | `OV+EV=<EVENT>,<TEXT>` | 异步事件 |
| 双向 | `OV+PING` / `OV+PONG` | 心跳（20s） |

- `REQ_ID`：0–255 循环，用于**配对 + 去重**（重传同 ID 只执行一次）
- `STATUS`：`OK` / `ERR` / `BUSY`

### 3.4 动作白名单（**已按实现定稿**，代码即规范：`tools/ai-link/intents.py`）

| CODE | 意图 | 执行 | 级别 |
|---|---|---|---|
| A01 | 放歌 / 暂停 | 媒体键 `PLAY_PAUSE` | A 安全 |
| A02 | 下一首 | 媒体键 `NEXT_TRACK` | A 安全 |
| A03 | 我困了 | 静音 + 锁屏 + 关显示器 | A 安全 |
| A04 | 音量 + | 媒体键 `VOLUME_UP` | A 安全 |
| A05 | 音量 − | 媒体键 `VOLUME_DOWN` | A 安全 |
| A06 | 打开资料 | 打开指定文件夹 / 网页（需 `ARG`） | A 安全 |
| A07 | 查状态 | 本地时间 + 在线状态（**不调 LLM**） | A 安全 |
| A08 | 语音输入 | 触发录音 → ASR（P2 接） | A 安全 |
| T | 自由指令 | 走慢通道：LLM → 动作码 → 白名单 | A/B |

> 级别 A = 直接执行；级别 B = 必须先二次确认（见 §3.5）。

## 4. 软件模块清单

### 4.1 手表端（F411）

| 模块 | 内容 | 预估 |
|---|---|---|
| `bsp_i2s_mic.c` | I2S2 DMA 双缓冲采集（16kHz/16bit/单声道） | 2–3 天 |
| `codec_adpcm.c` | 4bit ADPCM 压缩（8KB/s，为蓝牙预留） | 2 天 |
| `link_proto.c` | 协议组帧/解析/校验/超时重传（REQ_ID 去重） | 2–3 天 |
| `ai_session.c` | 四段状态机（录音/识别/思考/执行）+ 确认逻辑 | 3–4 天 |
| `ui_ai_page.c` | LVGL AI 页：状态条 + 文本区 + 操作提示（内置符号字体） | 4–5 天 |
| `ui_confirm.c` | 分级确认 + 可中断自动确认 + KEY1/KEY2 绑定 | 2–3 天 |
| `app_pager.c` | 锁屏 / 主界面 / 设置（页面栈） | 4–6 天 |
| `bsp_vib.c`（阶段 3） | 振动编码输出 | 1 天 |

**资源预算**：APP 可用 Flash 512KB、RAM 128KB。**UI 图标一律用 LVGL 内置符号字体**，中文字号控制在 2–3 个。

### 4.2 PC 端（Python）

| 模块 | 内容 | 预估 |
|---|---|---|
| `transport.py` | 串口收发行切分（自己按 `\r\n` 切，防粘包/半包） | 1 天 |
| `asr_sensevoice.py` | 本地 SenseVoice 推理（PCM→文本），可选云端对比 | 3–5 天 |
| `router.py` | 双通道路由 + 白名单 + 去重窗口 + 超时降级 | 3 天 |
| `intent_llm.py` | DeepSeek 调用（约束输出 JSON 动作，≤20 字摘要） | 2–3 天 |
| `executor.py` | 白名单动作集（pyautogui / ctypes / subprocess） | 3 天 |
| `tts.py` | Windows SAPI 播报 | 半天 |
| `mirror_ui.py` | **状态镜像窗口**（演示时评委看这个） | 1 天 |
| `fake_watch.py` | 模拟终端（无硬件跑通全链路） | 1 天 |

**线程模型**：读串口线程 → `queue.Queue` → 工作线程（ASR/LLM 不能阻塞读口）→ 回写线程；心跳定时器 + 断线自动重连。

## 5. 功能清单（三档）

**MVP（不达成就不能结项）**
按住说话录音 · 本地 ASR · 双通道路由 · 6 个白名单动作 · 四段状态 UI · 成功/失败反馈 · PC 端 TTS 播报 · 断开可重连

**应做（拿分数）**
分级确认 + 可中断自动确认 · 状态镜像窗口 · 断网降级（快通道照常） · 自由文本意图 · 翻腕唤醒 · 时延/准确率/成功率实测

**可选（时间够才碰）**
关键词唤醒（端侧 KWS） · 振动编码 · 蓝牙无线（USB 有线的替代方案） · 手机端（⚠️ iOS 不支持 SPP，别碰）

**明确不做**
❌ 本地部署大模型 ❌ 双分区 OTA（512KB 装不下） ❌ WiFi 联网 ❌ 控制手机 App ❌ 控制真实家电 ❌ 任意 shell 命令

## 6. 开发流程（5 阶段）

| 阶段 | 时间 | 目标 | **验收里程碑** |
|---|---|---|---|
| **P0 无硬件** | 10–11 月 | 协议定稿 + PC 网关骨架 + `fake_watch.py` | 跑通"发意图 → 路由 → 执行 → 回显"全链路（假数据） |

## 7. 验收指标（论文第 5 章的数据源）

| 指标 | 测法 | 目标 |
|---|---|---|
| 语音识别准确率 | 安静 / 嘈杂两档，各 50 句 | 报实测，不设虚高目标 |
| 端到端时延 | 按下 → 执行完成，全程打点 | 4–9s，如实报告分布 |
| 意图执行成功率 | 100 次触发的正确率 | ≥ 90% |
| **断网降级可用率** | 断网后 A01–A06 仍能执行的比例 | **接近 100%** |
| 确认机制效果 | 引入前后的误执行率对比 | 明显下降 |
| 功耗/续航 | µA 级电流表（阶段 3） | 报实测曲线 |

## 9. 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| 语音准确率不达预期 | 中 | 指令式关键词保底；论文写清测试条件 |
| 端到端时延过长（>10s） | 中 | 四段状态机给足反馈；本地 ASR 减一环 |
| 麦克风拾音噪声 | 中 | 远离电源走线；软件高通滤波 |
| ASR 模型下载困难 | 中 | 提前准备镜像源；P0 阶段就试装 |
| 演示现场翻车 | 中 | 全程录屏 + 状态镜像窗 + 提前在答辩电脑实测 |
| 时间充裕导致摊大饼 | **高** | 阶段里程碑制，达不到不许往下走 |
